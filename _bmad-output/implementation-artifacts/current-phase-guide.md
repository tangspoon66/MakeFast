## 每一步都要回答的六个问题

1. **这一步要解决什么？** 用一句话说明用户会得到的改善。
2. **这一步暂时不做什么？** 防止范围越做越大。
3. **要改哪些地方？** 列出页面、接口或数据文件。
4. **做到什么算完成？** 用可以检查的结果描述。
5. **怎么验证？** 说明测试、构建或手工操作方法。
6. **下一步是什么？** 写明下一个 Story 和它为什么排在后面。

## 当前建议顺序

### ST-101：注册、登录和会话接口（已完成）

- **目标：** 建好学习者独立账号和安全登录接口，让后续注册/登录页面有可靠服务可连接。
- **暂时不做：** 手机验证码、邮箱找回、家长后台、学校后台。
- **完成标准：** 注册、登录、退出、查询当前账号可用；密码只存哈希；会话使用 HttpOnly Cookie；修改请求必须通过 CSRF 校验。
- **完成结果：** 注册、登录、退出和会话查询均已实现；密码使用 PBKDF2 哈希；会话凭证只存哈希并通过 HttpOnly Cookie 传递。
- **暂不包含：** 手机验证码、邮箱找回、家长后台、学校后台。

### ST-102：账号页面与游客访问边界（已完成）

- **目标：** 访客可以了解课程，但必须登录后才能使用工作台和学习工具。
- **完成结果：** 登录/注册页、游客课程预览、登录后总览入口已接入；课程源文件、课程附件、固件下载、编译、AI 生成和工作台需要登录。
- **验证结果：** 学习者认证与课程受限资源测试通过；工作台/Agent 定向前端测试通过；前端构建通过。
- **暂不包含：** 手机/邮箱找回、家长与学校管理、真实积分计算。

### ST-201：项目和首页总览（已完成）

- **目标：** 登录后先看到“继续学习、开始课程、最近项目、进度和奖励”，而不是直接掉进代码编辑器。
- **暂时不做：** 任意项目的完整云端协作和学校班级管理。
- **本步改动：** 学习者数据库中的项目表、项目/进度接口、总览页数据连接。
- **完成标准：** 用户只能看到自己的项目；创建、保存、重命名、归档有服务器记录；保存使用版本号避免覆盖更新；刷新或重新登录后能继续学习。
- **验证方式：** 后端接口测试覆盖未登录拒绝、跨用户隔离、版本冲突和总览数据；前端测试覆盖加载、空状态和已开始学习状态。
- **完成结果：** 项目 API、账号隔离、CSRF、版本冲突保护和总览真实数据已接通；工作台按 URL 中的项目 ID 加载，自动保存代码、文件、板卡、积木 XML 与当前步骤，刷新或重新登录可恢复；旧浏览器草稿需要主动点击导入。保存冲突不覆盖较新版本，可将本页修改另存为新项目；退出账号会清理本机编辑器缓存。最近作品可分别打开。
- **验证结果：** 项目与认证后端测试 7 项、相关前端测试 10 项及构建通过。本地后端已重启加载新代码。完整前端套件仍有旧管理员测试失败（缺失页面导入、过期统计/令牌预期），不属于本 Story 的通过证据；登录后浏览器端完整硬件操作还需后续 E2E。
- **下一步：** `ST-301` 定义课程步骤数据，使项目能够绑定正式课程及每一步内容。
- **本次先处理的风险：** 已移除错误的三针传感器 `SDA/SCL` 假接线图和不存在的“检查连接”；材料与接线未核验前不允许从这两步的主按钮直接继续。旧 AI 聊天入口在课程工作台隐藏，串口和日志保留。后续课程 Story 尚未完成。

### ST-301：课程步骤数据（已完成）

- **目标：** 把“温湿度提醒器”拆成可读取的课程步骤，让每一步能显示不同内容面板。
- **暂时不做：** 课程生成 Skill 和大量课程批量导入。
- **完成标准：** 课程能保存材料、接线、积木、代码、编译、烧录、验证和挑战步骤，并能校验错误配置；成品图与每项物料图有资源来源、型号、说明和核验状态。允许准确的技术渲染图，但须记录与实际型号/引脚的比对依据；缺图不能用虚构的相似图替代。
- **完成结果：** 已建立课程 JSON 结构、管理端草稿/校验/发布接口、登录后课程读取接口。课程步骤涵盖介绍、材料、接线、积木、代码、编译、烧录、验证、挑战、知识检查和完成回顾；材料记录数量/用途/型号/媒体来源，接线记录引脚及实测依据。非法开发板引用、引脚引用、前置步骤、Agent 锚点或积分规则会被拒绝；图片/引脚/接线未经核验的草稿不能发布。发布版本不可修改，新项目绑定创建时的已发布版本；现有未绑定的原型项目不会被悄悄改绑。
- **验证结果：** 课程/项目/账号相关后端测试和前端构建通过。本步没有齐全的准确课程图与引脚实测，首门课程仍不能发布；工作台读取课程数据属于 ST-401。
- **下一步：** `ST-401` 用已发布课程步骤驱动工作台中间面板；完整的课程图与实物接线仍由 `ST-303` 和 `ST-403` 完成。

### ST-401：三栏项目工作台

- **目标：** 左边看课程路线，中间完成当前任务，右边查看设备和串口调试。
- **暂时不做：** 先不追求所有板卡兼容，也不把占位接线图当成真实 wiring graph。
- **完成标准：** 切换左侧步骤时，中间面板跟着变化；材料卡逐项点击确认，状态随项目保存，四类全确认后才进入接线实践，未确认时仍可预览；调试区可收起；编辑内容不会丢失。课程标题和正文要按儿童可读字号及字体完成桌面/窄屏检查。
- **已验收：** 账号项目读取已发布课程版本；材料四项可独立勾选/取消、自动保存、刷新恢复和全选解锁；右侧可自动开合或手动固定；知识检查可以选择并显示解释，不冒充已记录积分。相关前端 10 项、后端 8 项及前端构建通过；桌面 1280px 和手机 390px 实际查看无页面横向溢出，材料可用键盘空格操作，减少动态效果样式已加。
- **未验收：** DHT11、三针有源蜂鸣器、线材与成品的准确图片及使用权；已检查 Aily 的 DHT11 pinmap，其图片是 1 像素占位，不能拿来展示。`ST-303` 固定 SKU 和实物核验后再补齐。

### ST-402 / ST-403：设备调试和可靠接线

- **目标：** 把编译、烧录、串口和经过实物验证的接线关系接入工作台。
- **暂时不做：** 不让 AI 猜测未经验证的 GPIO，也不把杜邦线颜色当作规则。
- **完成标准：** 顶部有清楚的“连接设备”按钮与连接状态，次级设置使用“设备设置”文字；右侧保留串口输出、日志及波特率。课程指定的 XIAO ESP32-S3 Sense、三针 DHT11 和三针有源蜂鸣器要显示核验过的实物图，从图中真实引脚位置连线；结构化连接图、清单与逐根指引一致，按指定套件实测通过。
- **当前边界：** UI 布局、设备调试命名和按钮禁用状态已接入；未拿到实际套件，不把模拟点击当作 Web Serial、编译、烧录或接线的硬件验收。

### ST-303：首门课程实物核验

- **目标：** 固定实际购买的板卡、传感器与蜂鸣器型号，为成品和每件材料取得准确实拍或技术渲染图，逐线核对引脚，再实测编译、烧录、串口输出和短响。
- **完成标准：** 每张公开照片或技术渲染图有来源/使用权、对应型号及核验记录；每条接线记录实物验证结果。缺少其中任何证据时课程仍标为待验证，不开放正式接线指导。

### ST-501 / ST-502 / ST-503：编辑器边界和 Agent 引导

- **目标：** 让“积木编程”“代码编程”和像角色一样跳到真实按钮旁边的 Agent 协同工作。
- **暂时不做：** Agent 不代替用户点击编译、烧录，也不静默改写代码。
- **完成标准：** 使用用户给出的角色参考制作可用的静态透明状态素材，并由同一个 Agent 指向语义目标；不再并列出现旧 AI 对话框。新手模式自动展开引导，自主模式不强行打断。对话按课程项目保存；代码无法安全转换时明确提醒。当前参考图是多状态排版图，不能把整张图直接放进头像。

### ST-601 / ST-602：积分和徽章（已完成）

- **目标：** 对第一次学会关键动作给予更多积分，并在个人页显示原因和徽章。
- **暂时不做：** 不因重复点击或重放请求重复发分。
- **完成标准：** 积分流水可追溯、重复事件幂等、徽章条件明确。
- **完成结果：** 课程事件按首次/重复练习衰减计分，项目与课程证据校验、中文事件原因、首轮分值目录、已获得与未解锁徽章条件均已接入；课程完成奖励要求关键步骤已投影完成。

### ST-504：Agent 提案（已完成）

- **目标：** 让 Agent 的代码建议可检查、可取消、可应用、可撤销。
- **完成结果：** 提案保存基准 revision、摘要、依赖、硬件假设和代码预览；应用前不改项目，版本变化拒绝应用，应用后可在项目没有新修改时撤销。代码无法安全转积木时明确标为“仅代码可用”。

### ST-701 / ST-702：试点质量与回滚

- **当前结果：** 回归矩阵和发布/备份/功能开关/回滚手册已写入 `docs/verification/mvp-regression-matrix.md` 与 `docs/operations/pilot-release-rollback-runbook.md`。前端全量 `23 个测试文件/135 项`、生产构建、后端学习闭环、管理员兼容回归和 Agent 无障碍语义回归已通过。ST-701 仍需真实课程硬件烟测后关闭；硬件证据由 `ST-303` / `ST-403` 提供。
