# Product Requirements Document — MakeFast MVP

**状态：** Draft for implementation baseline  
**来源：** MakeFast Agent 设计说明、现有仓库盘点、产品讨论中已确认的决策  
**目标平台：** 桌面 Web；窄视口提供可用性降级

## 1. 产品目标

把 MakeFast 从“在线代码工具”扩展成以真实硬件项目为核心的学习与创作平台。用户从项目目标进入，按课程步骤理解和实践，在必要时由 MakeFast Agent 现场指引；作品运行后可验证、改造并获得进度、积分和徽章。

### 1.1 成功指标

以下是上线后应采集的指标，不代表目前已有基线：

- 激活：新注册用户开始一个项目、打开第一课程步骤的比例。
- 完成：开始首门课程后完成编译、烧录及设备验证的比例。
- 学习连续性：离开后重新进入并恢复到正确项目/步骤的比例。
- 引导有效性：Agent 指引后目标操作完成率；无关/关闭提示率。
- 正确性：代码/积木切换和 Agent 应用提案导致的数据丢失为零。
- 奖励一致性：服务端重复接收同一完成事件时重复发分为零。
- 可用性：主要工作台操作不依赖移动端或安装本地 IDE；Web Serial 浏览器限制明确可见。

首轮小规模试用目标是验证 Agent 引导闭环，而不是追求课程数量。建议以首批 10–20 名目标用户为校准样本，暂定：

- 至少 80% 能从首页找到课程并开始第一步。
- 至少 70% 能在 Agent 和课程引导下完成基础作品验证。
- Agent 指向正确语义目标的比例至少 95%，提示后的目标操作完成率至少 80%。
- 遇到一类预设常见问题时，至少 60% 能在 Agent 提示后继续完成，不需要成人直接代操作。
- 完成“首次搭建 → 修改报警阈值 → 再次编译/烧录/验证”后，至少 70% 能说清开发板、传感器、编译、烧录和串口各自的基本作用，至少 60% 能在减少逐步提示后再次完成关键操作。
- 安全底线为零容忍：Agent 未确认改写、自动烧录、静默代码丢失，以及把平台推测说成实物已成功的事件均为 0。

这些数值是 PM 的首轮验证目标，不是已有数据；首批试用后根据每一步漏斗和实际课程时长调整。

## 2. 用户与角色

- **访客**：只读查看产品介绍、课程正文/图文和步骤目录；不能获取源代码、积木工程、固件、附件下载、工作台、项目、进度、奖励或 Agent。
- **学习者**：注册用户，拥有项目、课程进度、积分、徽章和个人概览。
- **低龄学习者**：个人版学习者的一部分，可包含小学生；年龄/学段只影响 Agent 表达和安全提醒，不直接决定技术能力。
- **课程管理员**：在受保护管理区维护课程内容与版本。
- **平台管理员**：现有系统运维、开发板、固件、库、AI 配置和统计能力。

## 3. 关键用户旅程

### 3.1 新手引导

登录/开始 → 首页看到“做出一个温湿度提醒器”及作品成果、材料、学习收获和预计时间 → 开始项目 → 项目介绍 → 材料 → 接线 → 积木逻辑 → 编译 → 烧录 → 串口/实物验证 → 小挑战 → 知识检查/徽章 → 保存作品。

课程完成分为两层：

- **基础完成**：材料准备、接线、编译成功、烧录成功、串口出现有效温湿度数据，并由用户确认实物提醒有反应。完成后记录项目完成进度并发放基础奖励。
- **深度完成**：在基础完成后完成知识检查和改造挑战，再次编译、烧录并验证修改结果。完成后发放更高等级徽章或额外奖励。

知识检查和改造挑战不能阻塞用户先做出作品；它们用于区分“做出来”和“理解并能改造”。

不在进入时问“你想做什么”“你会不会”“你想选择哪个模式”。界面通过示例项目和可理解的成果说明来帮助用户做决定。

### 3.2 自主创作

登录后直接打开项目总览或编辑器入口 → 新建/导入/继续项目 → 选择积木或代码主编辑源 → 需要时召唤 Agent → 编译/烧录/串口调试。Agent 默认安静，不阻止用户自由跳转。

### 3.3 Agent 生成变更

用户描述功能 → Agent 获取当前项目/课程/板卡上下文 → 产生结构化代码或积木候选 → 显示差异、硬件假设、依赖与可逆性 → 用户预览并确认应用 → 更新项目并提供撤销/版本点 → 用户自行编译/烧录。

### 3.4 后续学校教育版（非 MVP）

后续计划：平台开通学校/教师 → 教师创建班级与学生账号 → 系统生成每名学生唯一的激活码或可轮换登录码 → 教师分配课程 → 学生通过教育版入口登录 → 使用同一课程工作台完成作品 → 教师查看班级进度并重置学生登录凭据。

该路线保留在长期设计中，但不属于当前 MVP 的开发、验收或上线依赖；教师课程版本管理同样延后。

## 4. 功能需求

优先级：`P0` 首发必要；`P1` MVP 内但可在首个端到端切片后完善；`P2` 后续。

### FR-AUTH 身份与个人空间

- **FR-AUTH-01 (P0)**：用户可用唯一用户名和密码注册、登录、退出；密码不得明文存储。
- **FR-AUTH-02 (P0)**：认证后的项目、进度、积分、徽章只允许所有者读取/修改；管理功能继续走独立管理员认证。
- **FR-AUTH-03 (P0)**：登录会话在关闭/超时后失效；凭证和密码错误不泄露账号是否存在；登录有频率限制。
- **FR-AUTH-04 (P1)**：用户可查看与编辑显示名、注册日期、头像占位和账户设置；phone/email 字段与验证状态为 nullable，未实现验证码找回前不承诺已绑定可找回。
- **FR-AUTH-05 (P0)**：访客只能读取明确标记为公开预览的课程正文与步骤目录；源代码、Blockly 工程、固件、附件下载、项目创建/保存、工作台、进度、奖励和所有 Agent 接口必须登录，且受服务端权限保护。
- **FR-AUTH-06 (P0)**：MVP 首门课程统一使用适合小学生的 `child` 表达基线，不在注册时询问精确年龄或表达档位；能力等级仍依据实际操作经验和后续表现独立判断。未来再扩展其他表达档位。
- **FR-AUTH-07 (P0)**：注册页说明建议由父母协助小学生创建并保管用户名和密码，但 MVP 不建立监护人账号、绑定或代管关系；没有验证联系方式时不得承诺自助找回。注册字段不要求手机号、邮箱、精确年龄或家庭信息。
- **FR-AUTH-08 (P0)**：注册后以一项简短、可跳过的实际经验问题初始化能力：是否从未接触、认识开发板/传感器、接过元件、编译或烧录过程序、使用过串口或排错。不得再问抽象的“想被引导还是自己探索”或要求先选开发板；回答只设置初始引导强度，后续由真实行为校准。

### FR-EDU 后续学校教育版（非 MVP backlog）

- **FR-EDU-01 (P2)**：平台可创建/停用学校教育空间并授予教师身份；教师只能访问所属学校及获授权班级。
- **FR-EDU-02 (P2)**：教师可管理班级和学生账号，并逐个发放可撤销、可轮换的唯一登录凭据。
- **FR-EDU-03 (P2)**：教师可分配课程并查看必要进度；默认不得查看原始串口、私密 Agent 对话或超出教学必要范围的完整代码。
- **FR-EDU-04 (P2)**：教师课程创建、编辑与版本管理需作为教育版独立需求评审，不继承平台课程管理员权限。

### FR-HOME 首页与个人页

- **FR-HOME-01 (P0)**：登录后默认进入学习/项目总览，不默认落到代码编辑器。
- **FR-HOME-02 (P0)**：首页显示继续上次项目/步骤、入门项目推荐、最近项目及学习进度。
- **FR-HOME-03 (P0)**：首页或个人概览可见积分总数、已获徽章和下一项目标；数据从服务端返回。
- **FR-HOME-04 (P1)**：个人页展示用户名/显示名、项目列表、学习记录、积分明细和徽章墙；私有内容只本人可见。
- **FR-HOME-05 (P1)**：提供“新手引导”和“自主创作”清晰入口；两者共用工作台。

### FR-PROJECT 项目与进度

- **FR-PROJ-01 (P0)**：学习者可以创建、重命名、继续和归档自己的项目；不可跨用户访问。
- **FR-PROJ-02 (P0)**：项目保存课程/模板引用、mode、editor source、board、代码文件/Blockly workspace、接线关系与更新时间。
- **FR-PROJ-03 (P0)**：用户重新登录或刷新后恢复最近保存状态；保存失败时保留本地副本并明确提示。
- **FR-PROJ-04 (P0)**：进度区分当前步骤、已完成步骤、待完成步骤、平台观察到的结果和用户确认的现实现象。
- **FR-PROJ-05 (P0)**：步骤可预览跳转；受前置条件保护的实际动作（编译、烧录、奖励完成）不能被仅仅打开页面触发。
- **FR-PROJ-06 (P1)**：对上线前旧版匿名编辑器留下的本地草稿，可在登录后提供显式导入；发生同名/冲突时保留副本，不静默覆盖。新 MVP 不再向访客开放匿名项目编辑。

### FR-COURSE 课程内容与步骤

- **FR-COURSE-01 (P0)**：课程以结构化步骤保存，而非只有长篇文章；课程至少包含最终产出、学习目标、预估时间、材料、板卡、接线、程序、编译/烧录、验证、挑战和知识检查。
- **FR-COURSE-02 (P0)**：管理员可创建、编辑、预览、发布课程及步骤；未发布内容不向普通用户公开。
- **FR-COURSE-03 (P0)**：课程步骤有稳定 ID、顺序、类型、内容、前置条件、完成条件和可选 Agent 提示。
- **FR-COURSE-04 (P0)**：课程发布版本固定；进行中的项目绑定版本快照，更新课程不得悄悄改变已开始项目的步骤/完成状态。
- **FR-COURSE-05 (P0)**：首发包含一个经硬件验证的 ESP32 温湿度提醒器课程，产品范围锁定为 Seeed Studio XIAO ESP32-S3 Sense（课程不使用摄像头、麦克风和 SD）、三针 DHT11 温湿度传感器模块、推荐的三针 3.3V 有源蜂鸣器模块，另含杜邦线与 USB 线。具体蜂鸣器型号、引脚、依赖版本和 BOM 仍必须在内容发布前通过实物测试核验，不可用示意线当作真实电气建议。
- **FR-COURSE-06 (P1)**：课程步骤提供简明说明及“开始实践”；用户可以随时返回本步骤说明而不丢编辑内容。

### FR-WORKBENCH 工作台

- **FR-WB-01 (P0)**：桌面工作台有顶部项目状态/Agent、左侧课程路线、中间步骤工作区、右侧设备调试四个层级。
- **FR-WB-02 (P0)**：切换左侧步骤时，中间区域加载对应步骤内容；课程说明和操作工具在同一主工作区内按阶段切换。
- **FR-WB-03 (P0)**：左侧步骤可以预览未完成步骤；阶段性行动遵守已定义的前置条件，且当前步骤/进度始终可见。
- **FR-WB-04 (P0)**：“积木编程”和“代码编程”是编程工作区视图；“编译”“烧录”是明确的动作按钮，不是并列 tab。
- **FR-WB-05 (P0)**：右侧设备调试面板在桌面端可收起、恢复和保持固定；课程阅读时收起/窄化，编程、烧录、验证时默认展开。
- **FR-WB-06 (P0)**：用户在代码/积木区时可以同时看串口反馈；切换课程步骤、开合调试栏不得清除编辑状态。
- **FR-WB-07 (P0)**：接线图、编辑器、代码和调试区之间通过项目状态共享语义对象，不使用屏幕坐标硬编码内容。
- **FR-WB-08 (P1)**：窄窗口把左侧导航和调试面板转为可开启的侧面层/可堆叠区，保留核心操作；移动端不是本次体验优化重点。

### FR-HW 硬件识别、接线与调试

- **FR-HW-01 (P0)**：首发课程以课程预设的 XIAO ESP32-S3 Sense 为默认板卡；设备连接后可探测芯片用于辅助诊断，但不把芯片探测当成具体板卡型号证明。课程不要求为所有板卡变体提供兼容方案。Sense 的扩展板可能占用部分内部 GPIO，课程必须使用经过实测的安全引脚。
- **FR-HW-02 (P0)**：系统必须区分“芯片识别”和“开发板型号确定”；USB VID/PID 不可证明所有具体板卡型号。
- **FR-HW-03 (P0)**：接线数据为结构化连接图，包含组件实例、中文显示名称、英文丝印名称、语义引脚、连接类型、课程指定目标、来源和验证状态；前端负责渲染接线图和同步清单。Aily Blockly 的 board/pinmap/component 数据可作为导入和建模参考，但课程发布使用 MakeFast 的固定、可验证连接图。
- **FR-HW-04 (P0)**：第一版只支持课程指定的 XIAO ESP32-S3 Sense、三针 DHT11 模块和验证过的蜂鸣器模块组合；课程作者可以手动指定每个模块的每个引脚目标连接。系统检查已知引脚冲突/不兼容；没有经过课程验证的数据不能标记为“已确认”。
- **FR-HW-05 (P0)**：串口/编译/烧录状态位于可折叠设备调试区，包含连接状态、编译状态、烧录进度、波特率、实时输出和可折叠原始日志。
- **FR-HW-06 (P0)**：串口原始输出默认只驻留浏览器当前会话，不持久化、不发送给 AI；用户主动“附加到问题”时显示确认并做大小限制。
- **FR-HW-07 (P0)**：编译或烧录的确认、进度、取消和失败说明必须可感知；Agent 不替用户启动这些动作。
- **FR-HW-08 (P1)**：通过浏览器权限恢复已授权串口；不支持 Web Serial 的浏览器显示准确兼容性提示及可用替代方案（例如仅编译/下载固件）。

### FR-EDITOR 编辑器与同步

- **FR-EDIT-01 (P0)**：项目保存 editor source：`blocks` 或 `code`，对应主数据。
- **FR-EDIT-02 (P0)**：blocks 主源的代码由 Blockly 生成；代码主源允许普通代码编辑。
- **FR-EDIT-03 (P0)**：双向转换只承诺经过测试的受支持语法；解析报告需要显示行号/无法识别片段。
- **FR-EDIT-04 (P0)**：当修改后代码无法完整回到积木时，保留源代码并明确提示“不能完整转换”；禁止静默丢弃。
- **FR-EDIT-05 (P0)**：对 blocks↔code 切换/转换前创建可撤销状态；应用生成/转换必须在 dirty state/失败场景测试。
- **FR-EDIT-06 (P1)**：AI 可生成 Blockly 可表达逻辑、代码补丁或自定义代码模块；先预览 diff、板卡假设、引脚、依赖和同步范围，再应用。

### FR-AGENT Agent 交互与生成

- **FR-AI-01 (P0)**：Agent 读取经过白名单筛选的项目上下文：用户当前课程版本/步骤、项目 mode、editor source、板卡置信状态、明确选择的代码/Blockly摘要、最近编译结果与用户主动提供的诊断信息。
- **FR-AI-01a (P0)**：Agent 不要求或询问家庭信息、住址、学校全名等与课程无关的儿童个人信息。
- **FR-AI-02 (P0)**：Agent 支持用户通过顶部固定头像召唤；显示为角色在当前步骤相关语义目标旁给简短气泡，不以常驻右侧聊天栏为主要入口。
- **FR-AI-03 (P0)**：气泡提供“继续问”，展开上下文追问输入/回答；回答长时可在目标气泡内滚动，不遮挡关键操作；需要离开时用户可关闭。
- **FR-AI-04 (P0)**：Agent 可由进入关键步骤、长时间停留、连续失败、编译/烧录失败和用户召唤触发；新手更主动，自主模式除重要错误外默认安静。
- **FR-AI-05 (P0)**：提示 target 绑定语义锚点（如 `compile-button`、`flash-button`、`wiring-diagram`、`serial-monitor`），锚点缺失/隐藏/不可见时采用安全回退，不跳错位置。
- **FR-AI-06 (P0)**：Agent 状态至少包括待机、指引、讲解、聆听、思考、成功、警告、等待确认；第一版以静态图/状态差异呈现，文字气泡由 UI 渲染。
- **FR-AI-07 (P0)**：区分平台事实、用户确认和 Agent 推测。Agent 不得把“串口收到数值”说成“蜂鸣器已响”或把猜测板卡称作已识别。
- **FR-AI-08 (P0)**：Agent 生成项目修改遵循“先预览再应用”；用户确认后才能改文件/workspace，成功后能撤销；编译、烧录、增加库和现实硬件确认仍需独立用户操作。
- **FR-AI-09 (P1)**：先复用现有 AI provider/service 配置，新增语义化上下文层，不将现有 chat completion 等同于完整 Agent 工具执行系统。
- **FR-AI-10 (P1)**：提示允许关闭/降低主动程度；用户关闭一次提示后在当前步骤不重复弹出，严重错误/用户召唤除外。
- **FR-AI-11 (P0)**：登录用户可在同一课程项目下创建、命名、切换、归档和重新打开多个 Agent 会话；每个会话绑定课程版本和项目，不能跨用户或跨项目读取。
- **FR-AI-12 (P0)**：课程会话持久化完整的用户消息与 Agent 回复，以及必要的目标/状态元数据；未发送输入只作为当前浏览器草稿，不承诺跨设备恢复。
- **FR-AI-13 (P0)**：会话历史可被用户主动删除或归档；删除后不再作为 Agent 默认上下文，服务端按数据保留策略处理备份和审计副本。
- **FR-AI-14 (P0)**：串口原始数据、完整代码和完整编译日志不自动附加到会话；用户明确选择后，消息显示附加内容范围并按大小/行数限制传输。

### FR-REWARD 进度、积分和徽章

- **FR-REWARD-01 (P0)**：服务端记录步骤开始/完成、编译、烧录、串口输出观察、用户实物确认、挑战和测验结果等类型化事件。
- **FR-REWARD-02 (P0)**：步骤完成可由系统证据或明确用户确认触发；不能因单纯点击“下一步”发放关键完成奖励。
- **FR-REWARD-03 (P0)**：积分必须记账为不可变事件，按幂等键保证重复请求只记一次；总分由账本汇总或一致性安全物化。
- **FR-REWARD-04 (P0)**：首发至少提供一套初始徽章、明确解锁条件及用户徽章墙；同一个条件不能重复解锁。
- **FR-REWARD-05 (P0)**：管理员或产品可为课程版本设置奖励规则；奖励 UI 说明获得原因和对应学习行为。
- **FR-REWARD-06 (P1)**：提供积分明细和徽章进度，而不仅是静态总数。
- **FR-REWARD-07 (P0)**：奖励按学习重要性和新颖度计算；同一能力第一次有效完成得 100%，第二次在新的合格练习中得 50%，第三次得 25%，之后机械重复不再发分。相同项目中的重复点击、重复编译或事件重放不增加“次数”。
- **FR-REWARD-08 (P0)**：首发积分与徽章基线采用 [Rewards & Pilot Metrics](rewards-and-pilot-metrics.md)；分值由可配置规则保存，不写死在前端。

### FR-ADMIN 管理和内容运营

- **FR-ADMIN-01 (P0)**：普通用户仅能管理个人资料/项目；管理员能力与现有管理员权限域隔离。
- **FR-ADMIN-02 (P0)**：管理员能够编辑步骤顺序、内容、材料、pinmap引用、工作区配置、先决条件、完成规则、知识问答、挑战、Agent提示和奖励规则。
- **FR-ADMIN-03 (P0)**：课程有草稿/预览/发布状态和版本；发布前显示校验错误（缺少引脚定义、步骤引用失效、无验证方式等）。
- **FR-ADMIN-04 (P1)**：查看课程完成漏斗、用户聚合进度与低成功率步骤，不在管理端暴露不必要的个人代码/串口原文。

## 5. 非功能需求

- **NFR-SEC-01**：密码用当前安全密码哈希策略存储；会话凭据使用 HttpOnly、Secure（生产）、SameSite Cookie，并保护写接口免受 CSRF；注册/登录限速。
- **NFR-SEC-02**：每个用户资源请求必须服务端授权所有权；不得依赖前端隐藏按钮。
> Security note: obsolete default-login instructions omitted; use locally generated credentials.
- **NFR-PRIV-02**：面向儿童的个人版遵循数据最少化；表达适配不需要精确生日，Agent 不应诱导披露真实姓名、电话、住址、学校或家庭信息，也不要求填写家庭信息。
- **NFR-PRIV-03**：个人版正式面向小学生公开服务前，必须完成适用地区的儿童个人信息合规审查，明确告知/授权、留存、删除、导出与事件响应责任；不制作监护人界面不等于无需审查。
- **NFR-DATA-01**：用户数据/奖励事务具备 SQLite 外键、事务、schema 版本迁移、备份和恢复测试；不复用 ops 指标数据库表。
- **NFR-RELIABILITY-01**：项目自动保存有本地恢复和服务端保存状态；版本冲突不静默覆盖。
- **NFR-A11Y-01**：关键操作能键盘访问，focus 可见；角色状态有文本说明，不以颜色或动画作为唯一反馈；支持 `prefers-reduced-motion`。
- **NFR-PERF-01**：课程静态内容和角色状态不应使工作台首屏重资源加载；Blockly 可按需加载。
- **NFR-COMPAT-01**：验证最新两个受支持 Chromium 主版本的 Web Serial 主流程；非支持浏览器不得阻塞纯课程阅读/编辑/编译功能。
- **NFR-OBS-01**：认证失败、Agent 调用失败、保存失败、重复奖励事件和构建/烧录结果可观测，但不得记录敏感上下文。

## 7. 关键验收场景

1. 登录后用户到达项目总览，而不是空白代码；访客只能读公开课程预览，任何源代码/工程/附件下载、工作台和 Agent 请求均被服务端拒绝。
2. 新手从项目成果卡进入课程，步骤切换更新中间内容但保留编辑状态。
3. 进入代码/积木步骤时能编译；烧录前需要成功固件和授权串口；串口验证时可以同时观察工作区与输出。
4. 用户打开未完成步骤只是预览；不会因此被记为完成或获得积分。
5. Agent 被召唤后定位当前步骤目标；目标丢失或不可见时回退到气泡/工作区提示。
6. Agent 生成修改只显示候选；取消不改变项目，确认后产生版本点，撤销恢复。
7. 相同步骤完成/徽章事件重放不会重复累积分数。
8. 登录用户不能读取其他人的项目、进度、奖励或 Agent 对话上下文。
9. 无 Web Serial 环境能继续查看课程/编辑/编译并获得明确说明。
10. 课程发布新版本后，旧项目进度依旧绑定其开始时版本或经过明确迁移流程。
11. 小学生账号使用儿童表达档位时 Agent 话术更短、更具体并增加安全提醒，但能力判断不会因年龄自动降级。
12. 同一课程项目可创建两个独立 Agent 会话；刷新、退出再登录后已发送完整消息仍可恢复，切换会话不会串用上下文；删除/归档后的会话不再作为默认上下文。

## 8. Assumptions & open decisions

- **Confirmed A1**：MVP 不向访客开放编辑、编译、源代码、工程/附件下载或 Agent；仅公开课程正文/图文和步骤目录。旧版匿名本地草稿只在登录后提供迁移入口。
- **Default A2**：首发先实现用户名+密码；手机号/邮箱仅预留字段，未验证的联系方式不作为找回渠道展示。
- **Confirmed A2-CHILD**：MVP 必须支持小学生但只做个人版；用户名密码由父母辅助注册和保管，不提供学校/教师/监护人管理界面；首门课程统一采用小学生表达，不采集精确年龄。
- **Default A3**：服务端第一版使用独立 SQLite 用户/学习数据库，与 ops/course QA 分开；课程内容使用版本化结构化记录。
- **Confirmed course kit, pending verification**：产品已确认首发采用 Seeed Studio XIAO ESP32-S3 Sense（课程不使用摄像头、麦克风和 SD）+ 三针 DHT11 模块 + 推荐的三针 3.3V 有源蜂鸣器模块 + 杜邦线/USB 线。课程制作前仍需核实蜂鸣器具体型号、避开 Sense 内部占用资源的 GPIO 分配、DHT 库/版本、驱动方式、pinmap、供电和可获得 BOM。
- **Confirmed reward baseline, validate in pilot**：首发分值、递减规则与徽章表已定义于奖励文档；试用后可以版本化调整，但已发账本不得被静默重算。
- **Required privacy review**：面向模型的代码/项目上下文在请求前要提示并允许用户查看/控制，原始串口数据默认不发送。
- **Required child privacy review**：确认面向儿童个人版的信息处理依据、告知/授权机制、数据最少化、保留/删除/导出流程后，才能公开面向小学生运营。
- **Confirmed AI conversation model**：课程项目支持多个可恢复的持久 Agent 会话；完整对话是用户学习记录。浏览器只保存未发送草稿和短期 UI 状态，服务端保存已发送消息。
- **Required AI conversation review**：上线前明确会话删除、备份清理、模型供应商保留期限和用户数据导出规则；会话历史默认不会因浏览器关闭而消失。
