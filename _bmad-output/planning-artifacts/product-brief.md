# Product Brief — MakeFast 项目学习与硬件创作平台

## 机会与问题

现有 MakeFast 已经解决“工具链安装、在线编译和网页烧录”的技术门槛，但用户仍要自行理解课程、找材料、识别板卡、读懂接线、组织代码并判断设备输出。对新手而言，编辑器打开后看到代码并不等于知道从哪里开始；普通 AI 聊天也不掌握当前课程步骤、页面状态和硬件反馈。

## 产品愿景

MakeFast 帮助用户从一个具体、有吸引力的硬件作品开始，在理解与动手之间来回切换，最终亲手完成、验证并改造作品。平台根据用户当前项目、课程步骤和可确认的设备状态提供恰到好处的帮助，让新手逐渐能够独立创作。

## 用户与需求

### 新手学习者

- 需要知道完成后能做出什么、需要什么材料、会学会什么。
- 需要在接线、编程、编译、烧录和验证之间有连续路线。
- 需要 Agent 指着页面里的具体区域解释“为什么做”和“下一步做什么”。

### 小学生

- MVP 通过个人版账号进入，不要求为了适配话术而填写精确生日。
- 需要更短、更具体、更具鼓励性的 Agent 表达和更明确的用电、接线与设备安全提醒。
- 使用与其他个人用户相同的课程和工作台；年龄表达不代替实际能力判断。

### 后续学校教师（非 MVP）

- 需要创建班级、批量或逐个建立学生账号、发放/重置唯一登录凭据。
- 需要分配课程并查看开始、步骤、基础完成和深度完成等进度，而不是查看不必要的私密对话或原始串口内容。
- 需要账号与课程管理的教育版后台，但首发不需要完整校务、排课或家校系统。

### 自主创作者

- 需要直接进入项目与工作台，而不是经过强制教程问卷。
- 需要积木/代码/硬件状态可以按需并列查看。
- 需要 Agent 只在主动召唤、失败或明显卡住时介入。

### 课程作者

- 需要把项目介绍、材料、接线、学习步骤、代码、知识点、挑战和测验作为结构化课程维护。
- 需要课程版本变更不让已有用户的进度错位。

## 价值主张

- **以作品而不是编辑器为入口**：首页告诉用户继续哪里、做出什么、还有什么奖励。
- **以步骤串联课程和工具**：每个课程步骤映射到中间不同工作区；设备调试始终是独立工具层。
- **以 IP 指引而不是聊天替代界面**：角色跳到目标控件附近，简短解释，并提供上下文追问。
- **以课程会话积累学习过程**：同一项目允许多个可命名、可恢复的 Agent 对话，方便回看“第一次接线”“调试失败”等学习节点。
- **以可验证进度鼓励学习**：保存课程进度、积分和徽章，但区分系统证据与用户对现实硬件的确认。
- **以真实项目生成提升效率**：Agent 可生成代码/积木候选，但先给变更、依赖和硬件假设预览，再由用户应用。

## MVP 成功标准

首发包含一门经过硬件核验的 ESP32 温湿度提醒器课程，产品硬件范围确定为 Seeed Studio XIAO ESP32-S3 Sense（课程不使用摄像头/麦克风/SD）、三针 DHT11 温湿度传感器模块、推荐的三针 3.3V 有源蜂鸣器模块、杜邦线和 USB 线。课程覆盖项目介绍、材料、接线、积木/代码、编译、烧录、串口验证、改造挑战和一个知识检查。普通用户可注册登录，重新打开后能恢复项目与步骤进度；完成指定学习事件可获得积分和徽章。

课程采用两层完成定义：先以真实设备输出和用户确认完成“基础作品验证”，让用户尽快获得成就感；再以知识检查和改造挑战完成“深度掌握”，奖励更高等级徽章。这样不会让测验成为第一次做出作品的门槛，同时保留学习深度。

MVP 采用三阶段掌握路径：第一次由 Agent 逐步带着做出来；第二次修改报警阈值并重新验证；第三次在减少逐步提示的情况下完成关键闭环或解决常见问题。用户随时可以召唤 Agent，求助不扣分。

建议在真实试用中验证以下结果（上线后埋点测量，不作为当前既有数据）：

- 新手能不依赖外部口头帮助找到开始入口，并完成第一步。
- 用户能正确区分“编译”和“烧录”，并完成至少一次实际设备输出验证。
- 刷新或重新登录后项目与进度可恢复。
- Agent 的上下文提示能定位到正确步骤/控件，且错误状态可解释。
- 积分和徽章由服务端可重放、幂等的学习事件发放。
- 首轮重点验证 Agent 是否能正确指向界面、推动下一步、帮助错误恢复，并使用户在三阶段后理解开发板、传感器、编译、烧录和串口。

## MVP 范围

### 必须

- 首页学习/项目总览；个人页包含项目、进度、积分、徽章。
- 用户名+密码注册、登录、退出和会话保护；为未来 phone/email 找回字段预留。
- 小学生在父母协助下使用个人版用户名密码；首门课程统一使用小学生表达，不采集精确年龄，也不因年龄自动降低能力等级。
- 注册后用一项实际经验问题初始化引导强度，后续按真实操作动态校准。
- 访客只能看课程图文预览和步骤目录；源代码、工程、固件、附件、工作台、编译与 Agent 均须登录。
- 新手引导与自主创作模式，使用同一工作台。
- 结构化课程步骤和管理员课程维护。
- 三栏桌面工作台：课程步骤/当前步骤工作区/可收起设备调试。
- Agent 静态 IP 状态、目标旁说明、当前上下文追问、阶段性提示。
- 课程绑定的多会话 Agent 历史，可重新打开、切换、归档和删除；完整已发送对话持久化，未发送草稿只保留在浏览器。
- 代码编译、浏览器烧录、串口观察既有能力嵌入新流程。
- 课程进度、积分账本和徽章解锁。
- 按学习重要性和新颖度发分：同一能力的第一/第二/第三次合格练习分别为 100%/50%/25%，机械重复不发分。
- 受支持语法内的积木↔代码同步边界与失败提示。

### 延后

- 手机号/邮箱验证码注册与找回闭环。
- 学校教育版：学校/班级、教师角色、学生账号与登录码、课程分配、班级进度、教师课程管理。
- 社交登录、订阅付费、排行榜、社交分享。
- 完整校务系统、排课、家校沟通、收费、多校区运营和复杂成绩单。
- 多课程规模化内容运营与开放式外设市场。
- 完整电路仿真、PCB/EDA、自动视觉识别实物线序。
- Agent 直接执行烧录或现实动作。
- 角色全身动画、视频/游戏引擎式动画；先用静态素材和轻量状态动效。

## 产品原则

1. 用户始终知道此刻目标和可执行的下一步。
2. 不问没有上下文价值的问题；能自动识别就先自动尝试，遇到不确定再诚实询问。
3. 课程说明不与操作工作区割裂，也不永久占据调试区。
4. Agent 的推断必须与平台事实、用户确认区分展示。
5. 关键硬件和代码变更由用户确认，Agent 协助而非代替学习者。

## 依赖与风险

- 首门课程的产品硬件组合已确认；具体蜂鸣器型号、接线 GPIO、pinmap、编译库版本、驱动方式和可获得材料仍需实物核验。
- 新用户与课程/项目存储需要新增正式持久层；现有存储以文件式资源和多个独立 SQLite 数据库为主。
- 当前 Web Serial 要求 Chromium 系浏览器和 HTTPS。
- AI 生成输出质量、成本、隐私和依赖授权需要治理；串口原始内容不得无默认授权地进入模型。
- 积分和徽章需要防止重复事件多次发奖。
- MVP 不建设监护人或学校管理界面，但在公开服务小学生前仍需完成适用地区的儿童信息告知/同意、数据最少化和留存删除策略审查；产品范围缩小并不会自动消除该要求。
