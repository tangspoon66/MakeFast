# Rewards & Pilot Metrics — MakeFast Personal MVP

## 1. 奖励原则

积分奖励“学会了什么”，不奖励停留时间、连续点击或无证据翻页。平台事实与用户实物确认分别记录；关键奖励需要对应完成条件。积分首发不具备现金、兑换或排名价值。

同一能力按合格练习次数递减：第一次 `100%`、第二次 `50%`、第三次 `25%`，第四次及以后相同机械练习 `0%`。新的改造目标或更高难度能力使用新的 competency key，可以获得完整奖励。一次练习必须属于新的课程尝试或明确挑战；同一项目内重复编译、重试、刷新和事件重放不算新练习。

## 2. 首门课程基础分值

| 学习事件 | 基础分 | 证据 |
|---|---:|---|
| 创建并真正开始课程项目 | 5 | 项目创建 + 进入首个实践步骤；只发一次 |
| 确认材料准备完成 | 5 | 四类材料均由用户确认；低权重，不代表平台检测到实物 |
| 完成结构化接线步骤 | 30 | 接线规则无已知冲突 + 用户确认 |
| 第一次编译成功 | 20 | 服务端成功结果 |
| 第一次烧录成功 | 50 | 浏览器设备工具成功结果 |
| 串口出现有效温湿度数据 | 40 | 本地解析到符合课程规则的数据；不保存原始流 |
| 确认实物提醒有反应 | 50 | 用户明确确认，不能由 Agent 推测 |
| 基础作品完成 | 80 | 基础完成条件全部满足 |
| 知识检查通过 | 30 | 通过课程规则；重复答题不重复发分 |
| 完成报警阈值改造并重新验证 | 80 | 修改 + 编译 + 烧录 + 串口/实物验证 |
| 深度完成 | 100 | 知识检查、改造挑战和再次验证均完成 |

首次完整深度完成理论总分为 `490`。具体事件由服务端账本按幂等键发放；客户端不得提交分值。

## 3. 首发徽章

| 徽章 | 解锁条件 |
|---|---|
| 第一次连接 | 首次成功连接受支持开发板 |
| 烧录启程 | 首次成功把固件烧录到设备 |
| 串口观察员 | 首次从串口观察到课程认可的有效传感器数据 |
| 作品完成者 | 首次达到基础作品完成条件 |
| 原理探索者 | 首次通过知识检查 |
| 改造创客 | 首次完成改造挑战并重新验证 |
| 熟练小创客 | 完成三次不同的合格实践阶段；不要求关闭 Agent，也不以积分高低判断能力 |

徽章只按明确学习行为解锁，不为注册、每日登录、停留时长或分享个人信息发放。

## 4. 三阶段掌握路径

1. **第一次：跟着做出来** — Agent 主动逐步引导，完成材料、接线、编译、烧录、串口和实物验证。
2. **第二次：改一处再验证** — 用户修改报警阈值，Agent 只在需要时提示，重新完成编译、烧录和验证。
3. **第三次：自己走关键闭环** — 用户在减少逐步提示的情况下完成关键操作或解决一个常见问题；随时仍可主动召唤 Agent，不因求助扣分。

## 5. 首轮试用目标

首批建议观察 10–20 名目标用户，重点不是统计显著性，而是发现课程和 Agent 的高摩擦步骤：

- 课程开始率：≥80%。
- 基础作品完成率：≥70%。
- Agent 语义锚点正确率：≥95%。
- Agent 提示后的目标操作完成率：≥80%。
- 常见问题经 Agent 指引后的恢复率：≥60%。
- 三阶段后基础概念掌握率：≥70%。
- 三阶段后减少逐步提示仍能完成关键闭环：≥60%。
- 未经确认修改/烧录、静默代码丢失、虚假确认硬件成功：0。

对话体验也要验证：用户能找到上次课程会话、继续未完成的问题，并创建第二个会话而不混淆上下文；会话历史在刷新和重新登录后仍可见。未发送草稿丢失不作为服务端会话丢失，但离开前应给出提示。

每个指标按步骤、失败类型和 Agent 提示类型拆分；首轮结束后再确定正式发布目标和课程时长承诺。
