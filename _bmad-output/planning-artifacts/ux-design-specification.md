# UX Design Specification — MakeFast MVP

## 1. UX 方向

MakeFast 是“作品导向的学习工作台”，不是把聊天窗口贴到 IDE 上。设计重点是让用户始终知道：最终产出是什么、当前走到哪里、此刻应理解/操作什么、设备实际反馈是什么。

### 设计原则

1. 先展示有吸引力的产出、材料和学习收益，再进入操作。
2. 左侧负责路线，中间负责当前步骤，右侧负责设备事实；三者不互相替代。
3. 课程说明与工具属于同一步骤的不同状态，不设计永久占据空间的独立课程文章栏。
4. Agent 角色是在页面上指路的 IP，不是聊天气泡头像，也不是固定助手侧栏。
5. 颜色/表情/动画提供补充反馈，文字、图标、状态标签同时说明事实。
6. 用户保有真实硬件、代码和烧录操作的控制权。

## 2. 信息架构

```text
公开入口
├── 产品介绍 / 公开课程
└── 个人登录 / 注册

登录后
├── 学习总览：首页
│   ├── 继续上次项目
│   ├── 新手项目推荐
│   ├── 最近项目
│   └── 积分 / 徽章 / 学习进度
├── 我的项目
├── 个人页
│   ├── 基本资料 / 账户安全
│   ├── 学习记录
│   ├── 积分明细
│   └── 徽章墙
└── 项目工作台
    ├── 左侧课程步骤路线
    ├── 中间当前步骤/工作区
    ├── 右侧设备调试面板
    └── 跨区域 Agent IP

```

## 3. 核心页面

### 3.1 首页 / 学习总览

- 首要卡片为“继续项目”和下一步，而非代码编辑器或空白模板。
- 新手项目卡用具体描述：“做出温湿度提醒器 / 约 20–30 分钟 / 需要 XIAO ESP32-S3 Sense 与传感器 / 学会接线、编程与调试”。实际用时和材料必须由内容作者核实。
- 自主创作入口提供新建项目、最近项目、导入代码；用普通语言描述差异，不要求用户先回答抽象熟练度问卷。
- 奖励区展示积分和徽章来源/下一目标，避免虚假的游戏化空数字。

首页按登录状态改变重点，但不改变产品主叙事：

```text
游客首页
├── MakeFast 是什么：陪你做出真实硬件作品
├── 主课程卡：做出温湿度提醒器
│   ├── 最终能做出什么
│   ├── 会学会什么
│   ├── 需要哪些材料
│   └── 查看课程 / 开始实践（注册）
├── 课程步骤预览
└── 为什么需要登录：保存项目、使用 Agent、编译/烧录和获得学习奖励

登录后首页
├── 继续上次项目：当前步骤 + 下一动作
├── 首发课程卡：做出温湿度提醒器
│   ├── 基础完成 / 深度完成进度
│   ├── 已获得积分和徽章
│   └── 继续学习
├── 我的课程会话 / 最近项目
├── 我的积分与徽章
└── 自主创作入口
```

游客课程预览应让用户产生“我想做出来”的兴趣，但不把源代码、积木、固件和完整操作资源提前交付。登录后的首页才出现“创建项目”和 Agent 入口。

首屏主 CTA 只保留一个：游客为“开始实践”，登录用户为“继续项目”；“查看课程”作为次级动作，避免小学生面对多个同等重要按钮而犹豫。

### 3.1.1 访客课程预览与注册

- 访客可以阅读课程最终成果、学习目标、材料、正文图文和步骤目录，但页面不接收或渲染源代码、Blockly 工程、固件和受保护附件 URL。
- 工作台、编译、烧录、项目保存、进度、积分、徽章和 Agent 入口均不向访客开放；点击“开始实践”进入注册/登录。
- 受保护资源由服务端鉴权；不能仅用 CSS 隐藏下载按钮。公开图片/正文仍属于普通网页内容，不承诺阻止截图或浏览器保存已公开内容。
- 注册字段保持为用户名、密码和可选昵称；文案建议小学生请父母协助创建和保管账号，不建立监护人账号绑定。
- 注册后出现一项可跳过的经验问题：“你以前做过下面哪些事情？”选项包括未接触、认识开发板/传感器、接过元件、编译/烧录过程序、看过串口或排过错误。系统不在此时追问学习模式或开发板。

注册和首次评估的确认规则：

- 注册字段只有用户名、密码、确认密码和可选昵称；不要求手机号、邮箱、精确年龄、家庭信息或学校信息。
- 页面明确提示：“如果你是小朋友，可以请爸爸妈妈帮你创建并记住账号。”这只是使用提示，不建立监护人账号、绑定关系或额外资料表。
- 注册成功后立即进入经验评估，不先进入空白代码或复杂设置页。
- 经验评估只有一道主问题，可跳过；选项是固定的实际经历，不使用“新手/高手”标签，也不让用户选择开发板。
- 跳过评估时默认从较主动的 guided 强度开始，系统根据用户后续行为调整；用户回答不会获得积分，也不会成为能力结论。
- 首门课程 Agent 统一使用儿童友好表达：短句、具体动词、解释术语、明确安全提醒；不要求用户选择语言风格。
- 评估完成后展示“你可以随时修改引导程度”，但入口放在项目设置或 Agent 菜单，不打断课程开始。

### 3.1.2 课程项目介绍页（已确认）

- 页面首屏先展示最终作品和一句可理解的成果描述：“做出一个会提醒你的温湿度装置”。
- 主信息顺序为：最终产出 → 你会学会什么 → 需要准备什么 → 预计时间 → 开始制作。
- “开始制作”是唯一主 CTA；点击后才创建课程项目、记录 `project_started`、进入第一步并启用 Agent 的主动引导。
- 页面不要求用户先选模式、开发板、传感器型号或代码方式；首发课程预设 Seeed Studio XIAO ESP32-S3 Sense（不使用摄像头、麦克风和 SD）+ 三针 DHT11 模块 + 验证过的有源蜂鸣器模块，用户按推荐套件准备即可。
- Agent 在介绍页可以以固定头像待机，并用一句话说明陪伴作用；在用户点击“开始制作”前，不跳到具体控件旁、不发放进度或积分。
- 预计时间、材料型号和成品效果必须来自已验证的课程内容；硬件尚未核验时显示“课程制作中/待验证”，不能用示意信息冒充最终说明。首屏成品图与材料图可使用固定套件的实拍照片，或与准确型号逐项比对过的技术渲染图；缺少可核验图片时明确标注待补充。

### 3.2 项目工作台桌面布局

```text
┌ 顶部：MakeFast / 项目名 / 保存状态 / 连接设备与状态 / 设备设置 / Agent 头像 / 个人入口 ┐
├ 左侧：课程路线 ┼──────── 中间：当前步骤工作区 ────────┼ 右侧：设备调试 ┤
│ 步骤与状态     │ 说明 / 图文 / 视频 / 接线 / 编程/挑战  │ 板卡/串口/日志 │
└───────────────┴───────────────────────────────────────┴──────────────┘
```

- 左侧宽度建议 250–290px；允许折叠为图标/步骤数字列。
- 右侧面板建议初始约 340px，可拖拽调整，收起后保留清晰入口；工作区可读宽度优先。
- 顶部高度保持紧凑，但“连接设备”和当前连接状态是常见的全局动作，应清楚可见；齿轮不能单独承担新手识别入口，需写明“设备设置”。端口列表、板卡手选和波特率等次级配置不挤占标题栏。
- 进入编程、烧录、验证步骤时默认展开右侧；其他内容步骤可收起。用户“固定”状态优先于自动开合。
- 代码编辑区切换步骤时需保持当前项目文档/Blockly workspace，不因 React 面板切换丢失。

### 3.3 年龄表达与能力分离

- MVP 首门课程统一使用 `child` 表达基线，控制句子长度、术语解释、鼓励方式和安全提醒；不在注册时要求选择年龄/表达档位，也不直接决定 `guided / assisted / autonomous`。
- 系统根据首次经验回答和实际操作表现动态校准引导程度；后续产品可扩展其他表达档位。
- 儿童表达避免拟人化承诺和诱导披露个人信息；Agent 不询问真实姓名、电话、住址、学校全名或家庭信息来完成课程。

### 3.4 后续教育版（非 MVP）

学校登录、班级/学生账号、激活码、课程分配、教师进度后台和教师课程版本管理保留为后续产品线。本 UX 规范不把这些页面列入当前 MVP 验收。

## 4. 课程步骤与中间面板

左侧步骤是路线导航；每个步骤映射一种中心面板内容。用户可点未完成步骤预览，但执行动作仍依赖前置状态。

| 步骤类型 | 中间面板显示 | 主要动作/完成证据 |
|---|---|---|
| 项目介绍 | 最终效果、目标、收益、时间、所需材料 | 点击“开始制作”创建项目并记录开始；不记课程完成 |
| 认识最终作品 | 固定套件的成品实拍或准确技术渲染图、温湿度传感器/XIAO ESP32-S3/有源蜂鸣器三个可点击部件及一句话解释 | 用户查看三个核心部件后主动进入准备材料；右侧调试区默认收起 |
| 准备材料 | 与固定套件型号一致的实物照片或准确技术渲染图、用途、数量和兼容性标签；每项可点击勾选/取消“我已经准备好了” | 四类材料均被用户确认并保存到项目后才出现可用的下一步实践按钮；缺材料可保存并预览后续，不发关键完成奖励；勾选不代表系统检测到实物 |
| 接线 | 结构化接线图、中文接线清单、英文丝印对照、引脚语义与提示 | 检查已知冲突；用户确认完成实物连接 |
| 程序逻辑 | Blockly 工作区 + “积木编程/代码编程”视图选择 | 积木项目编辑 workspace，代码可作为派生输出 |
| 编译 | 编辑区保留，突出“编译”动作、进度和结果 | 服务端编译成功/失败证据 |
| 烧录 | 说明编译与烧录区别，显示设备/串口状态 | 用户确认烧录；设备工具完成并给结果 |
| 验证输出 | 验证目标、应观察到的内容、实物确认项 | 串口证据 + 用户确认硬件现象，分别记录 |
| 改造挑战 | 清晰的挑战目标、建议改动位置、预期差异 | 用户自主修改后重新编译/烧录/验证 |
| 知识检查 | 一题或短问答，解释答案原因 | 答案与尝试次数规则明确；通过才能完成课程奖励 |
| 完成回顾 | 成果、学习了什么、奖励、下一项目 | 用户可回到项目继续改造 |

说明“课程内容与实践不是两个割裂页面”：每步可显示 `了解这一步` 和 `开始实践`；实践时中间面板切换内容态，步骤说明保留折叠入口。

## 5. 右侧设备调试

- 顶部展示“连接设备”主动作和连接状态；板卡推断/确认、USB 详情、浏览器支持、串口监视器、波特率和必要日志在右侧调试区呈现，次级选项通过有文字的“设备设置”打开。
- 课程的编译/烧录动作在工作区/工具栏中触发；串口的运行反馈在右侧查看，便于与中间代码并排对照。
- 串口开始按钮打开该面板内终端区域；暂停、清空、滚动、复制等控件不要污染课程主步骤。
- “板卡已选”“芯片已识别”“板卡猜测”用不同状态文案表达。
- 浏览器无 Web Serial 时解释原因，允许继续课程、编辑和服务器编译；受限的烧录能力单独说明。
- 原始日志默认内存保留，用户反馈/问 Agent 附加原始数据前需要显式选择。
- 认识最终作品和准备材料步骤默认收起；进入接线、编程、烧录、验证后按步骤自动展开，用户手动固定状态优先。

## 6. Agent IP 交互

### 6.1 角色和视觉

- 采用用户参考图中的像素风电子机器人：圆润灰色机身、青绿色屏幕/电路细节、橙色告警强调。
- 设计原型可暂用 CSS 占位；MVP 交付时使用从用户参考图整理出的独立静态透明状态素材，动画不作为首发阻塞项。原参考图有多格状态、背景和内嵌文字，不能整张直接当头像。
- 对话文字、箭头、按钮名称和本地化内容由 HTML/CSS 绘制，不烘焙进 PNG。
- 桌面固定小头像放项目头部右侧；召唤后同一角色出现在相关目标旁边；关闭后回到固定头像。
- 参考图提供的状态概念足以覆盖首发，不再要求额外全套 image generation 才开工。角色最终透明素材可在视觉迭代阶段替换 CSS 占位。

### 6.2 状态

| 状态 | 语义 | UI 表现/触发 |
|---|---|---|
| standby 待机 | Agent 可召唤，没有主动任务 | 头像在工作台边缘轻微静态状态 |
| guide 指引 | 指明一个下一步控件/区域 | 跳到语义锚点旁，方向手势 + 一句行动提示 |
| explain 讲解 | 说明原理、原因或步骤 | 角色面向用户/目标，展开信息气泡 |
| listening 聆听 | 等待用户输入 | 气泡内输入焦点可见，屏幕表情变化 |
| thinking 思考 | 正在请求/分析 | 明确“正在分析”，避免看起来卡死 |
| success 成功 | 平台已确认一个成功事件 | 温和庆祝；文案说清确认的实际事件 |
| warning 警告 | 有错误、风险或不确定项 | 橙色/红色辅助标签，解释下一步诊断 |
| waiting 等待确认 | 等待用户点击或线下确认 | 指向目标并显示用户需要执行/确认的内容 |

状态适用于待机小头像和浮动角色。页面事件和 Agent 交互状态独立，例如“编译失败”是平台事件，Agent 可进入思考后再以警告/讲解姿势指向错误。

### 6.3 召唤、主动出现与继续提问

- 用户点击顶部头像：Agent 根据当前步骤、工具状态和焦点区域给一条可跳转指引；若当前没有明显目标则在当前位置解释当前步骤。
- 气泡默认短；出现“继续问”后在同一气泡内展开输入与回答，不开永久聊天侧栏，也不保留旧编辑器的第二个 AI 对话框。串口与日志必须从旧聊天组件中拆出或以仅调试模式保留。
- 自主模式减少自动提醒；新手模式在新步骤、首次操作、编译/烧录失败、长时间停留等事件出现。
- 同一普通提示关闭后当前步骤不重复弹出；关键错误和用户主动召唤除外。
- 每次只指引一个主目标，不能一次高亮/弹跳多个区域。
- 锚点语义 ID 缺失、隐藏或在折叠面板中时：先尝试展开所属调试区，再滚入视口；仍失败就显示可访问的普通提示，不用坐标猜位置。
- 不抢焦点、不阻断输入、不代替用户点击编译/烧录/确认实物。
- 认识最终作品步骤中，Agent 可以依次锚定传感器、开发板和蜂鸣器三个部件；每次只出现一个主目标，用户查看后再移动到下一个目标。
- 准备材料步骤中，Agent 可以依次指向材料卡解释用途；不要求上传照片或自动识别实物，也不把用户勾选误说成平台已检测到材料。
- 接线步骤顶部固定显示：“杜邦线颜色不影响功能，只要两端接口接对就可以。”颜色不参与接线正确性判断。
- 新手模式逐根确认：当前只显示一条主连接，完整清单可折叠查看；高手模式默认展开完整清单，可从任意一条开始检查。
- 清单显示中文名称和括号内英文丝印，例如“温湿度传感器的电源引脚（VCC）”“温湿度传感器的数据引脚（DATA）”“地线引脚（GND）”。首次出现时解释 VCC、GND、DATA/SIG。
- 接线完成只记录“你已确认这根线接好”；平台只有在课程规则检查无冲突时才显示“课程连接规则通过”，不声称看见了用户手中的线。
- 清单、图形和 Agent 目标来自同一个结构化 wiring graph；不允许页面各自维护一份连接顺序。

### 6.3.2 首发课程的硬件表达与接线策略

- MVP 只围绕一套推荐且经过实测的固定套件：Seeed Studio XIAO ESP32-S3 Sense（课程只使用外露 GPIO，不使用摄像头、麦克风和 SD）、三针 DHT11 温湿度传感器模块、三针 3.3V 有源蜂鸣器模块、杜邦线和 USB 线。不为任意板卡变体承诺兼容；课程外的自主项目再单独处理兼容性。Sense 与基础版的外部引脚布局相近，但扩展板会占用部分内部 GPIO，课程连接必须避开并实测验证。
- 蜂鸣器优先选择带底板、接口明确标为 `VCC / GND / SIG`、3.3V 可供电、数字高电平触发的有源模块；不把裸蜂鸣器、只标 5V 或触发逻辑不清楚的廉价变体列入首发材料。具体商品 SKU 在采购核验后写入课程。
- Aily Blockly 的 board/pinmap/component 数据只作为结构化建模和内容作者的参考来源。课程发布时，以 MakeFast 课程专用 wiring graph 为唯一事实源；每条连接都必须绑定具体模块变体、语义引脚、课程目标端、来源和实物验证状态。
- 首发界面不把 `DHT11` 当作用户必须理解的名称。首次出现写成“温湿度传感器（DHT11 是它的型号）”，引脚优先使用“电源脚（VCC）”“数据脚（DATA）”“地线脚（GND）”“控制脚（SIG）”，并保留括号内英文丝印帮助用户在实物上寻找。
- 接线页固定显示：“杜邦线是什么颜色不影响功能，只要两端接口接对就可以。”颜色不进入规则校验，也不被 Agent 当成正确性依据。
- 新手视图一次只展示一根线：同时标出“从哪里”“接到哪里”“它的作用”，用户点击“我已按图接好”后 Agent 才移动到下一根；提供“我不确定”入口，但不声称平台已经看到了实物接线。
- 熟悉用户默认展开完整清单，可按传感器/蜂鸣器筛选；每行仍显示中文名称、英文丝印、作用和确认状态。图、清单、逐根引导和 Agent 锚点必须从同一个 wiring graph 渲染。
- 课程规则检查只说明“课程连接关系没有已知冲突”；真实硬件是否工作，以后续编译、烧录、串口和实物现象共同验证。

首发清单的用户文案示例：

| 从哪里 | 接到哪里 | 作用 |
|---|---|---|
| 温湿度传感器 - 电源脚（VCC） | XIAO ESP32-S3 Sense - 3.3V 电源脚 | 给传感器供电 |
| 温湿度传感器 - 地线脚（GND） | XIAO ESP32-S3 Sense - GND 地线脚 | 让两个模块共用地线 |
| 温湿度传感器 - 数据脚（DATA/S） | XIAO ESP32-S3 Sense - 课程指定数字脚 | 读取温度和湿度 |
| 有源蜂鸣器 - 电源脚（VCC） | XIAO ESP32-S3 Sense - 3.3V 电源脚 | 给蜂鸣器供电 |
| 有源蜂鸣器 - 地线脚（GND） | XIAO ESP32-S3 Sense - GND 地线脚 | 完成电路回路 |
| 有源蜂鸣器 - 控制脚（SIG/IO） | XIAO ESP32-S3 Sense - 课程指定数字脚 | 控制蜂鸣器发声 |

这里的“课程指定数字脚”在实物验证前不写成示意 GPIO，避免把未验证的数字误当成接线指令。

### 6.3.1 课程会话

- 每个课程项目有“Agent 会话”列表，默认显示最近会话和用户自定义标题，例如“第一次接线”“蜂鸣器不响”。
- 用户可以新建会话、重命名、切换、归档、重新打开和删除会话；每个会话都明确显示所属课程/项目。
- 切换会话只切换对话上下文，不切换项目代码、课程进度或硬件状态；Agent 不能把一个会话的假设当成另一个会话的事实。
- 刷新、退出浏览器和重新登录后，已发送的完整对话仍可恢复；正在输入但尚未发送的文字只作为浏览器草稿，离开前给出提示。
- 串口、代码和编译日志默认不出现在历史消息中；用户附加时，消息中显示“已附加最近 N 行串口/错误摘要”，并提供移除入口。

### 6.4 生成变更预览

Agent 在用户明确要求“帮我添加/修改功能”时才生成项目提案。展示前后 diff、受影响文件/积木、依赖、板卡/引脚假设和可否回到 Blockly。用户取消则无写入；确认后应用到工作区并创建可撤销版本；Agent 不自动编译、安装库或烧录。

## 7. 内容文案与状态语气

- 新手文案说明动作目的：“编译会检查程序是否能构建，不会写入开发板。”
- 使用具体动词：“点击编译”“检查 SDA 连接”，避免“初始化系统”等抽象表达。
- 以确定程度标记信息：`平台已检测`、`你已确认`、`Agent 推测`。
- 错误指出位置、原因候选、可执行的下一步；不给只含原始栈信息的提示。

## 8. 空态、异常与恢复

- 没有项目：显示新手体验项目和自主创建两个明确选项。
- 未识别板卡：自动识别失败后显示简短说明和相关候选，不要求初入首页先填硬件。
- 无材料/无 pinmap：显示真实来源缺失，不生成看似准确的接线示意。
- 没串口授权/浏览器不支持：引导连接和权限；保留其他可用功能。
- 课程版本更新：提示“此项目使用课程旧版”，由用户选择迁移/继续旧版。
- 离线/保存失败：显示最后保存时间，保留本地草稿并给重试入口。
- AI 失败或超时：保留用户输入，允许重试；不修改现有项目。

## 9. 可访问性与响应式

- 所有图标按钮提供 aria-label，步骤导航以有序列表语义暴露当前步骤。
- Agent 状态用 `role=status`/可读状态文案，不只依赖表情/颜色。
- 动效尊重 `prefers-reduced-motion`；静态状态仍能表达全部操作信息。
- 键盘可召唤/关闭 Agent、提交提问、切换面板和导航课程步骤。
- 窄屏只保证步骤、主内容和串口可达；桌面优先的三栏不在移动布局做完整重设计。

## 10. UX 验收

- 新用户不进入空白代码页；课程首屏可一句话理解项目成果和材料。
- 成品和材料显示可核对的实拍或准确技术渲染图与型号，记录图片来源和使用权；缺图状态明确，不能用色块或 AI 生成的相似元件伪装实物。
- “认识最终作品”步骤能通过三个可点击部件解释温湿度传感器、XIAO ESP32-S3 和执行器的职责；查看完成后才允许进入准备材料，不因单纯打开页面发放关键奖励。
- “准备材料”步骤展示四类首发材料和兼容性状态；用户确认齐全后才能进入接线完成态，缺材料时可以保存、退出和预览后续步骤。
- 材料逐项点击后有清晰勾选状态，刷新或重新登录后仍在；只有四类全确认才开放进入接线实践的主按钮。
- “接线”步骤能让新手按线确认、高手看完整清单；中文解释不隐藏英文丝印，杜邦线颜色说明在首屏可见，课程指定连接图和清单始终同步。
- 课程步骤切换时工作区内容相符且编辑状态持续。
- 收起调试面板时中间编辑区增宽，Agent 锚点仍能安全指向面板入口/先展开。
- 串口与代码可并列查看，串口状态不会被误认成真实硬件完成证据。
- 顶部“连接设备”和文字标注的“设备设置”在首次使用时可被理解；右侧仍可展开串口与日志。
- Agent 小头像召唤后锚定到实际控件；继续提问不抢掉代码编辑焦点。
- 用户关闭提示后不会在本步骤重复受到同一非关键提示。
- 角色静态图版本足够表达 8 态，减少动画偏好时没有信息损失。
- 课程文字、材料名称与按钮在桌面/窄屏都达到儿童可读字号；字体亲和但字形清楚，长名称不溢出。

## 11. 视觉方向 — 明亮儿童科技风

视觉参考采用用户提供的儿童 UI 配色图，确认的不是单纯配色，而是“明亮、直接、有科技感但不冰冷”的整体语言。

### 11.1 色彩基线

| 角色 | 色值 | 使用范围 |
|---|---|---|
| 主蓝 Sky Blue | `#74B0E1` | 首页主 CTA、课程主卡、进行中状态、主要导航强调 |
| 温暖黄 Warm Yellow | `#F4C65C` | 开始制作、奖励、徽章、成功庆祝、重点提醒 |
| 辅助浅蓝 Pale Blue | `#C0E2F9` | 课程卡背景、步骤区域、说明面板、空状态 |
| 深藏蓝 Deep Navy | `#08083D` | 标题、正文、代码区标题、重要边界和图标 |
| 白色 White | `#FFFFFF` | 页面底色、卡片内容区、编辑器阅读区 |

状态色另行保留语义：警告/危险使用橙红色，不能把黄色同时当作错误色；成功仍需有文字标签，不能只靠颜色。

### 11.2 组件语言

- 首页和课程介绍可以更活泼：大色块、大圆角、少量手绘/像素装饰和明确的成果图。
- 工作台保持清晰：白色或极浅蓝底，主蓝用于当前步骤和主要操作，黄色只用于关键动作/奖励，避免代码和串口区域过度装饰。
- 卡片圆角建议 `16–24px`；按钮使用明显的主色块和清晰文字，避免只有图标的关键按钮。
- 使用粗一些的标题字重和短句；正文保持足够行高，儿童友好不等于缩小文字或堆叠装饰。
- 阴影克制，优先用色块、边界和留白表达层级；重要控件可使用 `2–3px` 深藏蓝描边。
- Agent 角色的灰色机身、青绿色屏幕和橙色告警与主蓝/暖黄协调；角色不应覆盖代码、接线图或串口输出。

### 11.3 页面气质分层

```text
课程首页：活泼、明亮、鼓励开始
课程步骤：清晰、图文并重、每一步只有一个主动作
工作台：稳定、可读、工具优先
设备调试：深色/高对比终端可选，但状态标签仍使用主视觉体系
Agent：有趣、会陪伴、指向明确，不变成常驻聊天栏
```

### 11.4 可访问性约束

- 主蓝和浅蓝不能只依靠白色小字；文字按钮使用深藏蓝或经过对比度验证的白色。
- 黄色主要用于大面积按钮、徽章和强调块，不作为小字号正文背景。
- 所有成功、警告、错误状态同时提供文字、图标或结构信息。
- `prefers-reduced-motion` 下仍保留完整的角色位置、气泡和状态文字。

## 12. 当前 UX 评审顺序

视觉方向已确认，下一轮按以下顺序评审，不直接进入实现：

1. 首页/游客课程预览：用户为什么开始、能看到什么、何时注册。
2. 注册/首次能力评估：父母辅助文案、经验问题和初始引导强度（已确认）。
3. 课程项目介绍页：最终产出、材料、学习收益和预计时间。
4. 工作台首屏：左侧步骤、中间目标、右侧调试、顶部 Agent 与保存状态。
5. 第一次接线到串口验证的完整路径。
6. 多会话 Agent：新建、切换、恢复、删除以及目标旁气泡的关系。
