# MakeFast Project Context

## 项目摘要

MakeFast 当前是一个面向 Arduino / ESP 教学和创客课程的 Web 开发平台。核心已有能力是浏览器代码/Blockly 编辑、后端 Arduino CLI 编译、Web Serial 烧录、串口监视、课程模板与资源库，以及管理员维护功能。本次规划将产品主叙事从“在线编辑器”升级为“陪用户完成真实硬件作品的项目学习平台”。

## 代码库现状（规划基线）

- 前端：React 19、TypeScript、Vite、TailwindCSS、Zustand、Blockly、Monaco/多文件编辑组件、`esptool-js`。
- 后端：Python 3.10+、FastAPI、Pydantic；Arduino CLI 与工具链由服务端管理。
- 部署：Docker Compose；浏览器端通过 Web Serial 直接连接设备，生产环境要求 HTTPS，推荐 Chrome/Edge。
- 当前课程：模板和课程分组存储已支持文章、视频、代码文件、附件、板卡和管理页面；课程步骤尚未成为可执行的结构化学习流。
- 当前 AI：有基于消息、板卡、项目文件和编译错误上下文的代码生成/流式接口；还没有项目事件驱动的 Agent 状态机、UI 锚点引导、结构化提案审批接口。
- 当前身份：存在管理员身份验证；普通用户注册、登录、账户资料和用户级项目归属尚未实现。
- 当前数据：课程模板/分组有文件式存储；课程问答和运维统计使用 SQLite。用户项目、课程进度、积分账本、徽章解锁尚无正式服务端数据模型。
- 当前编辑器：已有 Blockly 代码生成、代码到积木的解析尝试和切换提示，但两种编辑源的持久化与同步语义尚未收敛为产品契约。

## 目标用户

1. 小学生与其他初次接触智能硬件的学习者：不知道先做什么，也不熟悉板卡、传感器、引脚和编译/烧录的区别；MVP 使用个人版账号进入。
2. 有一定经验的创客：希望直接进入项目工作区，自主选择项目、板卡和编程方式，遇到问题时主动求助。
3. 课程管理员/内容作者：希望维护课程说明、材料、接线、代码、挑战和测验，而不只是上传一份文章或代码包。
4. 后续学校教师：未来教育版需要创建班级和学生账号/登录码、分配课程、重置登录凭据并查看班级学习进度，但不属于当前 MVP。

## 已确认的产品决策

- 登录后首页以“学习/项目总览”为中心，不以编辑器为默认首页。
- 新手入口用有明确最终产出的项目邀请用户开始，不先抛“你想做什么”“你想自己探索吗”等抽象问题。
- 新手引导与自主创作是同一工作台的不同 Agent 主动程度，不是两套割裂产品。
- 第一个示例课程锁定 Seeed Studio XIAO ESP32-S3 Sense（默认使用其外露 GPIO，不使用摄像头/麦克风/SD 功能）+ 三针 DHT11 模块 + 推荐的三针 3.3V 有源蜂鸣器模块；具体蜂鸣器型号、引脚和部件库存需实施前核实，不得把示意接线写成既定电气事实。Sense 虽与基础版保持相同的外部引脚布局，但扩展板会占用部分内部 GPIO，课程必须避开并实测验证。
- 工作台桌面布局：左侧课程步骤，中间当前步骤内容/操作，右侧可收起设备调试，IP 作为跨区域引导层。
- 每个左侧课程步骤决定中间面板内容；右侧串口/设备状态是跨步骤工具，编程时允许与代码并排查看。
- 编译和烧录是操作按钮，不是与积木/代码并列的工作区 tab。
- 积木编程与代码编程使用明确名称。双向转换仅承诺受支持语法范围；不可逆代码必须告知且不得静默丢失。
- Agent IP 使用用户提供的像素电子机器人图作为视觉参考。第一版优先静态素材/简易 CSS 动效，不阻塞在全身动画制作上；不把界面文字烘焙进角色图。
- Agent 能指向语义控件、在目标旁给提示、允许继续追问；不替用户点击关键按钮，也不替用户确认现实中的硬件现象。
- Agent 对话按课程项目持久化，支持多个独立会话；已发送消息可在刷新/重新登录后恢复，未发送草稿不作为服务端学习记录。
- 第一版必须包含普通用户用户名/密码注册登录、个人/项目进度、积分和徽章。
- 访客只能查看课程的只读图文预览和步骤目录；源代码、积木工程、固件、附件下载、工作台、编译和 Agent 都需要登录。
- MVP 只交付个人版；小学生也使用个人账号，不在当前版本建设学校/班级、教师后台、学生登录码或课程分配。
- 学校教育版保留为后续独立产品线，并计划复用课程、工作台、Agent、项目、进度与奖励核心，不复制一套学习产品。
- 年龄/学段仅调整 Agent 语言复杂度、安全提示和鼓励方式，不能代替实际能力评估，也不能直接限制积木或代码能力。
- 首门课程统一采用适合小学生的表达，不在注册时采集精确年龄；父母辅助创建和保管用户名密码，但 MVP 不建设监护人账号关系。
- 未来手机号与邮箱至少绑定其一用于找回；MVP 先支持普通用户名+密码注册，用户模型预留联系方式和验证状态。
- 接线关系使用结构化数据，由 UI 绘制；不在 MVP 做完整电路仿真或 PCB/EDA。
- Aily Blockly 的结构化 board/pinmap/component 数据作为接线建模和导入参考；课程发布采用 MakeFast 课程专用、手动指定并实测验证的连接图。首发清单使用中文解释并保留英文丝印名，明确杜邦线颜色不影响功能。
- 项目接受 GPL-3.0 开源路线；如果直接纳入 Aily Blockly 代码，必须保留版权/许可证、提供对应源代码并遵守 GPL 的衍生作品义务。课程 pinmap 数据和图片仍需逐项核验来源与许可证。

## 规划约束与非目标

- 第一版以桌面 Web 为核心，窄窗口仅做基本适配。
- MVP 先服务于一门经过核实的 ESP32 体验课程，后续可扩充课程目录。
- 学校教育版及排课、家校沟通、收费、公开排名、复杂成绩单和多校区运营均不进入当前 MVP。
- 不将 Agent 定义成常驻右侧聊天栏；用户召唤和阶段性引导优先采用角色+目标气泡。
- 不承诺任意 C++ 到 Blockly 的无损反向转换。
- 不允许 Agent 未经确认覆盖代码/积木、安装依赖、编译、烧录或标记现实硬件完成。
- 用户原始串口数据默认仅在浏览器会话内使用，不默认持久化或发送到模型。

## 当前工作树注意事项

仓库位于较大的 Git 工作区内，父级工作区现有大量与本需求无关的变更。本次只新增 `_bmad-output/` 文档，不重置、不清理、不提交其他文件。早先尝试的 `HomePage.tsx` 工作台 spike 和 `AgentWidget.tsx` 尚未通过构建与 UX 验收，属于未验收原型；先完成文档和 readiness，再由首个实现 Story 决定保留、调整或重写。
