# MakeFast Agent 设计说明

## 一、它是什么

MakeFast Agent 是 MakeFast 平台里的**专用型智能体**。

“专用型智能体”指的是：它不是一个什么都能回答的通用聊天机器人，而是专门帮助用户学习和完成智能硬件项目的 AI 导师。

它的核心任务是：

> **理解用户正在学习的课程、所在页面和当前进度，在合适的位置提供引导、解释、提醒和排错，帮助用户亲自完成真实硬件作品，并逐渐从新手模式过渡到可以独立操作和改造作品。**

它不会替用户完成所有点击操作，也不会代替用户连接硬件。它的职责是：

- 告诉用户应该做什么
- 指出相关按钮和页面区域
- 解释每个操作的目的
- 感知用户是否完成了某一步
- 出现错误时帮助分析
- 取得进展时给予反馈
- 在用户熟练后减少引导

因此，MakeFast Agent 更像是一个**嵌入开发平台的交互式创客导师**。

## 二、它和普通 LLM 的区别

LLM（大语言模型，负责理解和生成文字的 AI）只是 Agent 的“大脑”。

普通 LLM 通常是：

> 用户提问 → AI 回答

MakeFast Agent 是：

> 课程和用户状态 → 判断当前需要 → 提供引导或解释 → 用户亲自操作 → 平台反馈结果 → Agent 决定下一步

Agent 还需要：

- **目标**：例如完成温湿度提醒器课程
- **状态**：用户目前做到哪一步
- **上下文**：用户在哪个页面、使用什么板卡
- **工具**：课程查询、代码编辑、编译、串口读取等
- **规则**：什么情况下主动提醒，什么操作需要确认
- **反馈**：用户点击了什么、编译是否成功、设备是否有输出

所以，MakeFast Agent 不是“加入更多知识和 Prompt 的聊天机器人”，而是一个能够理解学习情境并持续陪伴用户完成任务的系统。

## 三、产品定位

MakeFast Agent 的定位可以概括为：

> **用户亲自操作，Agent 负责看懂情境、解释每一步、及时提醒、帮助排错，并随着用户成长逐渐减少干预。**

它不替用户创造，而是帮助用户学会创造。

这和完全自动操作型 Agent 不同。完全自动操作型 Agent 可能会替用户点击、修改和执行；MakeFast Agent 更强调学习过程中的参与感和理解。

例如，第一次使用 MakeFast 时，小精灵会告诉用户：

> “请点击这里选择开发板。不同开发板的引脚位置可能不一样，所以平台需要先知道你使用的是哪一块板子。”

但最终按钮由用户自己点击。

## 四、主要学习目标

MakeFast Agent 需要围绕四个目标工作。

### 1. 带用户完成课程项目

它理解课程目标、当前步骤和完成条件，并用简单语言告诉用户下一步做什么。

### 2. 帮助用户理解原理

它根据当前步骤生成简短知识卡片，解释传感器、引脚、代码逻辑和开发板特点。

### 3. 检查用户是否真正掌握

它在关键步骤后提出小问题或小挑战，判断用户是否理解，而不是只看按钮是否被点击。

### 4. 帮助用户逐渐独立

用户完成基础课程后，Agent 减少界面引导，鼓励用户自己修改参数、增加功能和尝试新项目。

## 五、两种核心模式

## 1. 新手引导模式

新手第一次上课时，Agent 会提供完整的界面和操作引导。

以“温湿度提醒器”为例：

1. 小精灵说明课程目标。
2. 指向开发板选择区域。
3. 解释为什么要选择 ESP32 型号。
4. 指向材料清单，说明每个部件的作用。
5. 引导用户打开接线图。
6. 解释电源线、地线和信号线。
7. 引导用户打开 Blockly 或代码区域。
8. 解释“编译”是检查程序，而不是写入开发板。
9. 引导用户点击编译。
10. 编译成功后，解释“烧录”是把程序写进 ESP32。
11. 引导用户打开串口监视器。
12. 解释串口数据代表什么。
13. 用户确认传感器数据和蜂鸣器效果。
14. Agent 总结完成情况并进入下一步。

这个过程中，Agent 可以：

- 高亮按钮
- 显示箭头
- 展开相关区域
- 弹出简短说明
- 等待用户操作
- 检查用户是否完成
- 再进入下一步

它不需要替用户点击，而是让用户学会使用 MakeFast。

## 2. 熟练模式

当用户完成过几门课程，或者主动选择熟练模式后，Agent 减少打扰。

它不再解释每一个按钮，只在以下情况出现：

- 用户主动请求帮助
- 用户在某一步停留太久
- 用户连续操作失败
- 编译出现错误
- 当前步骤有重要概念
- 用户可能走错流程
- 项目出现新的进展

例如：

> “程序已经编译成功。下一步需要烧录到 ESP32。你可以自己操作；如果不确定烧录和编译的区别，我可以简单解释。”

熟练模式的目标不是完全取消 Agent，而是把 Agent 从“手把手老师”变成“随时可以询问的助手”。

## 六、以温湿度提醒器为例的功能

### 1. 课程理解

Agent 能读取课程中的：

- 学习目标
- 材料清单
- 开发板要求
- 课程步骤
- 代码或 Blockly 项目
- 接线说明
- 知识要点
- 常见问题
- 完成条件
- 测试题
- 改造任务

课程内容最好以结构化形式保存，而不是只有一篇长文章。

例如：

```
步骤：读取温度
目标：让 ESP32 读取 DHT11 的温度
材料：ESP32、DHT11、连接线
操作：完成接线并运行程序
完成条件：串口显示温度数值
常见问题：没有数据、数据异常、找不到库
知识点：传感器、GPIO、串口
```

“结构化”就是把课程整理成系统可以读取和判断的内容。

### 2. 页面和状态感知

Agent 不需要读取页面上的每一个像素，而是由 MakeFast 的各个模块主动发送重要事件。

例如：

```
用户进入温湿度课程
用户打开第 2 步
用户选择 ESP32 DevKit
用户查看接线图
用户修改了代码
用户点击编译
编译失败
编译成功
用户打开串口监视器
串口出现温度数据
用户完成测试题
用户在当前步骤停留了较长时间
```

“事件”就是系统发生的一次重要变化。

这样 Agent 不需要用户重复说：

> “我刚刚编译失败了。”

因为平台已经把结果告诉它。

### 3. 课程进度管理

Agent 需要记录：

- 当前课程
- 当前步骤
- 已完成的操作
- 尚未完成的任务
- 用户确认过的内容
- 编译和烧录结果
- 串口数据状态
- 测试题结果
- 用户遇到过的问题
- 当前学习模式

例如：

```
课程：温湿度提醒器
模式：新手引导
当前步骤：测试温度读取
已完成：选择开发板、完成接线、编译成功
待完成：烧录程序、打开串口、确认温度数据
平台已知：串口出现温度数值
用户尚未确认：传感器是否正确安装
```

### 4. 硬件资料查询

Agent 可以查询：

- ESP32 的具体型号
- 可使用的 GPIO 引脚
- 输入和输出能力
- 电压要求
- 板载 LED 信息
- 温湿度传感器型号
- 蜂鸣器类型
- 接线方式
- 所需软件库
- Blockly 积木支持情况
- 常见兼容性问题

aily-blockly 中的开发板、传感器、库和 pinmap 数据可以作为参考，但不能直接假设所有数据都适合 MakeFast。

需要确认：

- 字段定义
- 数据版本
- 适用板卡
- 数据准确性
- 开源许可证
- 与 MakeFast 编译环境是否一致

### 5. 接线引导

Agent 可以生成：

- 接线表
- 图形化接线图
- 引脚解释
- 电源和地线说明
- 接线检查清单

例如：

```
DHT11 VCC → ESP32 3.3V
DHT11 GND → ESP32 GND
DHT11 DATA → ESP32 GPIO 4
蜂鸣器正极 → ESP32 GPIO 18
蜂鸣器负极 → ESP32 GND
```

Agent 还可以检查明显问题：

- 两个元件是否用了同一个引脚
- 是否接错电压
- 是否遗漏地线
- 当前板卡是否支持这个引脚
- 是否需要电阻

但 Agent 不能假装看到用户现实中的接线。用户需要点击“我已接好”，或者提供照片、设备数据等额外证据。

### 6. 知识卡片

知识卡片应该短、直观，并且只解释当前需要的内容。

例如：

> **什么是 GPIO？**
> GPIO 是 ESP32 上可以和外部元件交流的小接口。程序可以让它输出电信号，也可以读取传感器传来的信号。

> **为什么要接 GND？**
> GND 可以理解为电路的共同参考点。没有它，ESP32 和传感器可能无法正确理解彼此的信号。

> **温度提醒是怎么工作的？**
> 程序先读取温度，再把温度和设定值比较。如果温度更高，就让蜂鸣器响。

知识卡片可以由 Agent 根据课程步骤自动生成，但硬件事实必须来自可信资料。

### 7. 代码和 Blockly

Agent 可以：

- 生成课程代码
- 修改已有代码
- 解释代码
- 生成简单逻辑对应的 Blockly
- 显示代码修改前后的差异
- 说明代码如何对应硬件动作

温湿度提醒器的逻辑可以表示为：

```
读取温度
如果温度超过 30 度
    蜂鸣器响
否则
    蜂鸣器停止
```

简单逻辑适合使用 Blockly；复杂代码可以保留代码视图。

Agent 的任务不是让用户永远不接触代码，而是先降低入门门槛，再帮助用户逐渐理解代码。

### 8. 编译和错误解释

Agent 可以读取真实编译结果：

1. 用户点击编译。
2. 平台执行编译。
3. Agent 读取结果。
4. 如果失败，解释错误。
5. 展示建议修改。
6. 用户确认后应用修改。
7. 再次编译。

它需要区分：

- 程序写法错误
- 缺少库
- 开发板选错
- 引脚名称错误
- 库版本不兼容
- 警告和真正错误

在新手模式中，它可以这样解释：

> “程序现在无法编译，是因为它找不到温湿度传感器需要的库。你不用自己搜索，我可以带你打开库管理区域。”

### 9. 串口和设备反馈

Agent 可以读取串口输出，例如：

```
温度：28.4℃
湿度：63%
```

这说明传感器大概率已经开始工作。

但需要区分：

- 编译成功：程序写法基本通过检查
- 烧录成功：程序已经写入开发板
- 串口有数据：设备正在输出信息
- 用户确认蜂鸣器响：实物行为已确认
- 用户理解原理：学习目标已确认

这些不是同一件事。

### 10. 测试和小挑战

每完成一个重要步骤，Agent 可以给一个简短问题：

- “如果把报警温度改成 28 度，你觉得要改哪里？”
- “为什么传感器需要连接 GND？”
- “如果温度没有超过设定值，蜂鸣器应该怎样？”
- “哪一部分代码负责读取温度？”

答错时，Agent 换一种方式解释，不把用户简单标记为失败。

项目完成后，可以提供改造挑战：

- 修改报警温度
- 增加 LED 指示
- 在屏幕上显示温湿度
- 让不同温度范围有不同提醒
- 增加按钮控制

## 七、主动提示机制

Agent 可以像小精灵一样主动出现，但必须有节制。

### 可以主动出现的情况

- 用户刚进入新步骤
- 用户第一次使用某个按钮
- 用户停留太久
- 用户连续编译失败
- 用户完成重要操作
- 用户出现新的串口数据
- 用户完成课程步骤
- 用户需要确认现实世界结果

### 不应该频繁打扰的情况

- 用户正在连续编辑代码
- 用户已经熟练完成相同步骤
- 用户关闭了当前提示
- 用户明确选择安静模式
- 当前没有新的、有价值的信息

可以提供三种主动程度：

- **安静陪伴**：只有用户提问或严重错误时出现。
- **适度提醒**：在关键步骤和卡住时提醒。
- **手把手教学**：适合第一节课，几乎每一步都有说明。

## 八、个性化功能

账号、学习记录和年龄段属于平台功能；Agent 根据这些信息调整教学方式。

例如：

- 儿童：短句、图片、少量专业词汇。
- 青少年：增加原理和代码对照。
- 成人初学者：不使用幼稚化语言，强调实际用途。
- 教师：显示课程完成情况和常见错误。

用户也可以自己选择：

- 简单讲
- 详细讲
- 只告诉我下一步
- 手把手模式
- 挑战模式
- 少一点鼓励
- 多一点原理

年龄不应直接决定用户能力。它只是影响默认表达方式。

## 九、积分、徽章和成长体系

积分和排行榜可以增强趣味性，但不应只追求速度。

可以奖励：

- 完成一个步骤
- 第一次成功读取传感器
- 独立完成一次修改
- 完成知识测试
- 完成改造挑战
- 连续学习
- 发布自己的作品
- 帮助其他用户

排行榜可以按：

- 完成作品数量
- 自主改造次数
- 挑战完成数
- 连续学习天数
- 社区贡献

不要只按“谁最快完成”排名，因为硬件问题不完全由用户控制。

整体体验可以参考多邻国：

> 学一个小知识 → 做一个小操作 → 回答一个小问题 → 看到设备反馈 → 获得奖励 → 解锁下一步

## 十、Agent 的工作循环

MakeFast Agent 可以采用“观察—判断—引导—检查”的循环。

### 1. 观察

读取：

- 当前课程
- 当前步骤
- 用户所在页面
- 当前模式
- 选定板卡和材料
- 当前代码或 Blockly
- 编译结果
- 串口数据
- 测试结果
- 操作停留时间

### 2. 判断

判断用户当前状态：

- 刚开始学习
- 正常进行
- 不知道下一步
- 缺少硬件信息
- 编译失败
- 编译成功但设备尚未验证
- 设备反馈异常
- 已完成基础任务
- 可以进入改造挑战

### 3. 引导

选择最适合的帮助：

- 高亮按钮
- 显示下一步
- 生成知识卡片
- 提供接线说明
- 生成代码或 Blockly
- 解释错误
- 提出测试题
- 推荐改造挑战
- 请求用户确认

### 4. 检查

等待用户操作和平台反馈：

- 用户是否点击了正确按钮
- 是否完成了当前步骤
- 编译是否成功
- 是否出现新的错误
- 串口是否有数据
- 用户是否答对问题
- 设备是否达到预期
- 是否需要继续解释

Agent 不应该一开始就把所有课程内容全部发出来，而是根据当前状态逐步推进。

## 十一、工具层

Agent 负责判断，工具负责执行具体读取或操作。

可以设计如下工具：

```
get_course_context
读取当前课程和课程步骤

get_learning_state
读取用户进度和学习模式

get_page_state
读取用户当前所在页面和界面状态

get_board_config
查询开发板资料

search_components
查询传感器、蜂鸣器等模块

get_library_requirements
查询需要的软件库

generate_wiring_plan
生成接线方案

validate_wiring_plan
检查接线方案的明显冲突

generate_knowledge_card
生成当前步骤的知识卡片

generate_code
生成或修改代码

generate_blockly
生成可编辑积木

compile_project
编译项目

analyze_compile_error
分析编译错误

get_serial_logs
读取串口输出

save_learning_progress
保存学习进度

record_user_confirmation
记录用户确认

generate_quiz
生成理解问题

suggest_next_challenge
推荐改造任务
```

这些工具让 Agent 的行为清楚、可追踪、可测试。

## 十二、哪些事情必须由用户做

MakeFast Agent 可以解释和引导，但不应代替用户完成学习中的关键动作。

用户应该亲自：

- 选择开发板
- 准备和连接硬件
- 点击编译
- 确认是否烧录
- 观察 LED、蜂鸣器或屏幕
- 回答理解问题
- 尝试改造作品

Agent 可以：

- 告诉用户在哪里操作
- 解释为什么这样操作
- 检测平台是否收到操作结果
- 发现错误后帮助分析
- 在用户卡住时提供下一步
- 在用户熟悉后减少提示

这能保证用户不是“看着 AI 自动完成”，而是真正学会使用工具和理解作品。

## 十三、隐私和安全边界

由于平台会记录账号、课程进度、年龄段和操作行为，需要注意：

- 尽量只收集必要信息
- 年龄使用年龄段，不必收集过多个人信息
- 未成年人数据需要特别保护
- 排行榜不要公开真实姓名和精确年龄
- 用户可以关闭主动提醒
- 用户可以删除学习记录
- 代码覆盖和项目修改需要确认
- Agent 不能把推测说成确定事实

Agent 还必须明确区分：

- 平台已经知道的事实
- 用户主动确认的事实
- Agent 的推测
- 尚未验证的内容

## 十四、比赛版应该做到什么程度

比赛版不需要支持所有硬件和所有课程。

建议聚焦：

- 一门温湿度提醒器课程
- 一块明确型号的 ESP32
- 一个温湿度传感器
- 一个蜂鸣器
- 新手引导模式
- 基础知识卡片
- 编译和串口反馈
- 一个小测试
- 一个改造挑战
- 简单积分或徽章
- 熟练模式展示

现场演示可以分成两部分：

第一部分是新手模式：

> 小精灵引导用户认识界面、选择板卡、查看接线、编译、烧录和打开串口。

第二部分是从引导到独立：

> Agent 提出一个小问题，用户自己修改报警阈值并重新编译。Agent 只在出现错误时提供帮助。

这样能清楚展示用户从：

> 不会使用平台 → 在引导下完成项目 → 理解关键原理 → 自己修改作品

## 十五、最终定义

MakeFast 平台是：

> **帮助初学者学习并完成智能硬件项目的创作学习平台。**

MakeFast Agent 是：

> **平台里的交互式创客导师。它能够理解课程、页面和学习状态，在新手阶段通过小精灵提供完整的界面引导，在用户熟练后逐渐减少干预；它解释按钮和原理，感知操作结果，帮助处理错误，检查用户是否理解，并鼓励用户自己改造作品。**

最重要的一句话是：

> **MakeFast Agent 不替用户创造，而是陪用户完成第一次创造，并最终让用户能够自己创造。**
