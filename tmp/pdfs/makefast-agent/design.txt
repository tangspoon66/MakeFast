MakeFast Agent 设计说明
⼀、它是什么
MakeFast Agent 是 MakeFast 平台⾥的专⽤型智能体。

“专⽤型智能体”指的是：它不是⼀个什么都能回答的通⽤聊天机器⼈，⽽是专⻔帮助⽤户学习和完成智能硬件项⽬
的 AI 导师。

它的核⼼任务是：

  理解⽤户正在学习的课程、所在⻚⾯和当前进度，在合适的位置提供引导、解释、提醒和排错，帮助⽤户亲
  ⾃完成真实硬件作品，并逐渐从新⼿模式过渡到可以独⽴操作和改造作品。

它不会替⽤户完成所有点击操作，也不会代替⽤户连接硬件。它的职责是：

     告诉⽤户应该做什么

     指出相关按钮和⻚⾯区域

     解释每个操作的⽬的

     感知⽤户是否完成了某⼀步

     出现错误时帮助分析

     取得进展时给予反馈

     在⽤户熟练后减少引导

因此，MakeFast Agent 更像是⼀个嵌⼊开发平台的交互式创客导师。


⼆、它和普通 LLM 的区别
LLM（⼤语⾔模型，负责理解和⽣成⽂字的 AI）只是 Agent 的“⼤脑”。

普通 LLM 通常是：

  ⽤户提问 → AI 回答

MakeFast Agent 是：

  课程和⽤户状态 → 判断当前需要 → 提供引导或解释 → ⽤户亲⾃操作 → 平台反馈结果 → Agent 决定下⼀步

Agent 还需要：

     ⽬标：例如完成温湿度提醒器课程

     状态：⽤户⽬前做到哪⼀步

     上下⽂：⽤户在哪个⻚⾯、使⽤什么板卡

     ⼯具：课程查询、代码编辑、编译、串⼝读取等

     规则：什么情况下主动提醒，什么操作需要确认

     反馈：⽤户点击了什么、编译是否成功、设备是否有输出
所以，MakeFast Agent 不是“加⼊更多知识和 Prompt 的聊天机器⼈”，⽽是⼀个能够理解学习情境并持续陪伴⽤
户完成任务的系统。


三、产品定位
MakeFast Agent 的定位可以概括为：

  ⽤户亲⾃操作，Agent 负责看懂情境、解释每⼀步、及时提醒、帮助排错，并随着⽤户成⻓逐渐减少⼲预。

它不替⽤户创造，⽽是帮助⽤户学会创造。

这和完全⾃动操作型 Agent 不同。完全⾃动操作型 Agent 可能会替⽤户点击、修改和执⾏；MakeFast Agent 更强
调学习过程中的参与感和理解。

例如，第⼀次使⽤ MakeFast 时，⼩精灵会告诉⽤户：

  “请点击这⾥选择开发板。不同开发板的引脚位置可能不⼀样，所以平台需要先知道你使⽤的是哪⼀块板⼦。”

但最终按钮由⽤户⾃⼰点击。


四、主要学习⽬标
MakeFast Agent 需要围绕四个⽬标⼯作。

1. 带⽤户完成课程项⽬
它理解课程⽬标、当前步骤和完成条件，并⽤简单语⾔告诉⽤户下⼀步做什么。

2. 帮助⽤户理解原理
它根据当前步骤⽣成简短知识卡⽚，解释传感器、引脚、代码逻辑和开发板特点。


3. 检查⽤户是否真正掌握
它在关键步骤后提出⼩问题或⼩挑战，判断⽤户是否理解，⽽不是只看按钮是否被点击。


4. 帮助⽤户逐渐独⽴
⽤户完成基础课程后，Agent 减少界⾯引导，⿎励⽤户⾃⼰修改参数、增加功能和尝试新项⽬。


五、两种核⼼模式
1. 新⼿引导模式
新⼿第⼀次上课时，Agent 会提供完整的界⾯和操作引导。

以“温湿度提醒器”为例：

  1. ⼩精灵说明课程⽬标。

  2. 指向开发板选择区域。

  3. 解释为什么要选择 ESP32 型号。

  4. 指向材料清单，说明每个部件的作⽤。
  5. 引导⽤户打开接线图。

  6. 解释电源线、地线和信号线。

  7. 引导⽤户打开 Blockly 或代码区域。

  8. 解释“编译”是检查程序，⽽不是写⼊开发板。

  9. 引导⽤户点击编译。

 10. 编译成功后，解释“烧录”是把程序写进 ESP32。

 11. 引导⽤户打开串⼝监视器。

 12. 解释串⼝数据代表什么。

 13. ⽤户确认传感器数据和蜂鸣器效果。

 14. Agent 总结完成情况并进⼊下⼀步。

这个过程中，Agent 可以：

      ⾼亮按钮

      显示箭头

      展开相关区域

      弹出简短说明

      等待⽤户操作

      检查⽤户是否完成

      再进⼊下⼀步

它不需要替⽤户点击，⽽是让⽤户学会使⽤ MakeFast。


2. 熟练模式
当⽤户完成过⼏⻔课程，或者主动选择熟练模式后，Agent 减少打扰。

它不再解释每⼀个按钮，只在以下情况出现：

      ⽤户主动请求帮助

      ⽤户在某⼀步停留太久

      ⽤户连续操作失败

      编译出现错误

      当前步骤有重要概念

      ⽤户可能⾛错流程

      项⽬出现新的进展

例如：

 “程序已经编译成功。下⼀步需要烧录到 ESP32。你可以⾃⼰操作；如果不确定烧录和编译的区别，我可以简
 单解释。”

熟练模式的⽬标不是完全取消 Agent，⽽是把 Agent 从“⼿把⼿⽼师”变成“随时可以询问的助⼿”。

1. 课程理解
Agent 能读取课程中的：

      学习⽬标

      材料清单

      开发板要求

      课程步骤

      代码或 Blockly 项⽬

      接线说明

      知识要点

      常⻅问题

      完成条件

      测试题

      改造任务

课程内容最好以结构化形式保存，⽽不是只有⼀篇⻓⽂章。

例如：


 步骤：读取温度
 ⽬标：让 ESP32 读取 DHT11 的温度
 材料：ESP32、DHT11、连接线
 操作：完成接线并运⾏程序
 完成条件：串⼝显示温度数值
 常⻅问题：没有数据、数据异常、找不到库
 知识点：传感器、GPIO、串⼝


“结构化”就是把课程整理成系统可以读取和判断的内容。

2. ⻚⾯和状态感知
Agent 不需要读取⻚⾯上的每⼀个像素，⽽是由 MakeFast 的各个模块主动发送重要事件。

例如：
 ⽤户进⼊温湿度课程
 ⽤户打开第 2 步
 ⽤户选择 ESP32 DevKit
 ⽤户查看接线图
 ⽤户修改了代码
 ⽤户点击编译
 编译失败
 编译成功
 ⽤户打开串⼝监视器
 串⼝出现温度数据
 ⽤户完成测试题
 ⽤户在当前步骤停留了较⻓时间


“事件”就是系统发⽣的⼀次重要变化。

这样 Agent 不需要⽤户重复说：

  “我刚刚编译失败了。”

因为平台已经把结果告诉它。


3. 课程进度管理
Agent 需要记录：

      当前课程

      当前步骤

      已完成的操作

      尚未完成的任务

      ⽤户确认过的内容

      编译和烧录结果

      串⼝数据状态

      测试题结果

      ⽤户遇到过的问题

      当前学习模式

例如：


 课程：温湿度提醒器
 模式：新⼿引导
 当前步骤：测试温度读取
 已完成：选择开发板、完成接线、编译成功
 待完成：烧录程序、打开串⼝、确认温度数据
 平台已知：串⼝出现温度数值
 ⽤户尚未确认：传感器是否正确安装



4. 硬件资料查询
Agent 可以查询：

      ESP32 的具体型号

      可使⽤的 GPIO 引脚

      输⼊和输出能⼒

      电压要求

      板载 LED 信息

      温湿度传感器型号

      蜂鸣器类型

      接线⽅式

      所需软件库

      Blockly 积⽊⽀持情况

      常⻅兼容性问题

aily-blockly 中的开发板、传感器、库和 pinmap 数据可以作为参考，但不能直接假设所有数据都适合 MakeFast。

需要确认：

      字段定义

      数据版本

      适⽤板卡

      数据准确性

      开源许可证

      与 MakeFast 编译环境是否⼀致


5. 接线引导
Agent 可以⽣成：

      接线表

      图形化接线图

      引脚解释

      电源和地线说明

      接线检查清单

例如：


 DHT11 VCC → ESP32 3.3V
 DHT11 GND → ESP32 GND
 DHT11 DATA → ESP32 GPIO 4
 蜂鸣器正极 → ESP32 GPIO 18
 蜂鸣器负极 → ESP32 GND
Agent 还可以检查明显问题：

      两个元件是否⽤了同⼀个引脚

      是否接错电压

      是否遗漏地线

      当前板卡是否⽀持这个引脚

      是否需要电阻

但 Agent 不能假装看到⽤户现实中的接线。⽤户需要点击“我已接好”，或者提供照⽚、设备数据等额外证据。


6. 知识卡⽚
知识卡⽚应该短、直观，并且只解释当前需要的内容。

例如：

  什么是 GPIO？
  GPIO 是 ESP32 上可以和外部元件交流的⼩接⼝。程序可以让它输出电信号，也可以读取传感器传来的信
  号。

  为什么要接 GND？
  GND 可以理解为电路的共同参考点。没有它，ESP32 和传感器可能⽆法正确理解彼此的信号。

  温度提醒是怎么⼯作的？
  程序先读取温度，再把温度和设定值⽐较。如果温度更⾼，就让蜂鸣器响。

知识卡⽚可以由 Agent 根据课程步骤⾃动⽣成，但硬件事实必须来⾃可信资料。

7. 代码和 Blockly
Agent 可以：

      ⽣成课程代码

      修改已有代码

      解释代码

      ⽣成简单逻辑对应的 Blockly

      显示代码修改前后的差异

      说明代码如何对应硬件动作

温湿度提醒器的逻辑可以表示为：


 读取温度
 如果温度超过 30 度
      蜂鸣器响
 否则
      蜂鸣器停⽌


简单逻辑适合使⽤ Blockly；复杂代码可以保留代码视图。
Agent 的任务不是让⽤户永远不接触代码，⽽是先降低⼊⻔⻔槛，再帮助⽤户逐渐理解代码。

8. 编译和错误解释
Agent 可以读取真实编译结果：

  1. ⽤户点击编译。

  2. 平台执⾏编译。

  3. Agent 读取结果。

  4. 如果失败，解释错误。

  5. 展示建议修改。

  6. ⽤户确认后应⽤修改。

  7. 再次编译。

它需要区分：

    程序写法错误

    缺少库

    开发板选错

    引脚名称错误

    库版本不兼容

    警告和真正错误

在新⼿模式中，它可以这样解释：

 “程序现在⽆法编译，是因为它找不到温湿度传感器需要的库。你不⽤⾃⼰搜索，我可以带你打开库管理区
 域。”


9. 串⼝和设备反馈
Agent 可以读取串⼝输出，例如：


 温度：28.4℃
 湿度：63%


这说明传感器⼤概率已经开始⼯作。

但需要区分：

    编译成功：程序写法基本通过检查

    烧录成功：程序已经写⼊开发板

    串⼝有数据：设备正在输出信息

    ⽤户确认蜂鸣器响：实物⾏为已确认

    ⽤户理解原理：学习⽬标已确认

这些不是同⼀件事。
10. 测试和⼩挑战
每完成⼀个重要步骤，Agent 可以给⼀个简短问题：

   “如果把报警温度改成 28 度，你觉得要改哪⾥？”

   “为什么传感器需要连接 GND？”

   “如果温度没有超过设定值，蜂鸣器应该怎样？”

   “哪⼀部分代码负责读取温度？”

答错时，Agent 换⼀种⽅式解释，不把⽤户简单标记为失败。

项⽬完成后，可以提供改造挑战：

   修改报警温度

   增加 LED 指示

   在屏幕上显示温湿度

   让不同温度范围有不同提醒

   增加按钮控制


七、主动提示机制
Agent 可以像⼩精灵⼀样主动出现，但必须有节制。

可以主动出现的情况
   ⽤户刚进⼊新步骤

   ⽤户第⼀次使⽤某个按钮

   ⽤户停留太久

   ⽤户连续编译失败

   ⽤户完成重要操作

   ⽤户出现新的串⼝数据

   ⽤户完成课程步骤

   ⽤户需要确认现实世界结果


不应该频繁打扰的情况
   ⽤户正在连续编辑代码

   ⽤户已经熟练完成相同步骤

   ⽤户关闭了当前提示

   ⽤户明确选择安静模式

   当前没有新的、有价值的信息

可以提供三种主动程度：
      安静陪伴：只有⽤户提问或严重错误时出现。

      适度提醒：在关键步骤和卡住时提醒。

      ⼿把⼿教学：适合第⼀节课，⼏乎每⼀步都有说明。


⼋、个性化功能
账号、学习记录和年龄段属于平台功能；Agent 根据这些信息调整教学⽅式。

例如：

      ⼉童：短句、图⽚、少量专业词汇。

      ⻘少年：增加原理和代码对照。

      成⼈初学者：不使⽤幼稚化语⾔，强调实际⽤途。

      教师：显示课程完成情况和常⻅错误。

⽤户也可以⾃⼰选择：

      简单讲

      详细讲

      只告诉我下⼀步

      ⼿把⼿模式

      挑战模式

      少⼀点⿎励

      多⼀点原理

年龄不应直接决定⽤户能⼒。它只是影响默认表达⽅式。


九、积分、徽章和成⻓体系
积分和排⾏榜可以增强趣味性，但不应只追求速度。

可以奖励：

      完成⼀个步骤

      第⼀次成功读取传感器

      独⽴完成⼀次修改

      完成知识测试

      完成改造挑战

      连续学习

      发布⾃⼰的作品

      帮助其他⽤户

排⾏榜可以按：

      完成作品数量
      ⾃主改造次数

      挑战完成数

      连续学习天数

      社区贡献

不要只按“谁最快完成”排名，因为硬件问题不完全由⽤户控制。

整体体验可以参考多邻国：

 学⼀个⼩知识 → 做⼀个⼩操作 → 回答⼀个⼩问题 → 看到设备反馈 → 获得奖励 → 解锁下⼀步


⼗、Agent 的⼯作循环
MakeFast Agent 可以采⽤“观察—判断—引导—检查”的循环。

      当前模式

      当前代码或 Blockly

      编译结果

      串⼝数据

      测试结果

      操作停留时间


2. 判断

      刚开始学习

      正常进⾏

      不知道下⼀步

      缺少硬件信息

      编译失败

      编译成功但设备尚未验证

      设备反馈异常

      已完成基础任务

      可以进⼊改造挑战
3. 引导

    ⾼亮按钮

    显示下⼀步

    ⽣成知识卡⽚

    提供接线说明

    ⽣成代码或 Blockly

    解释错误

    提出测试题

    推荐改造挑战

    ⽤户是否答对问题

Agent 不应该⼀开始就把所有课程内容全部发出来，⽽是根据当前状态逐步推进。
